# 여백 · 수업 받아쓰기

노트북·태블릿의 마이크, 데스크톱 브라우저가 공유한 탭/화면 소리, 기존 녹음 파일을 받아 수업 기록을 만드는 개인용 웹 앱입니다. 마이크 수업은 로컬 `Qwen3-ASR-1.7B` 또는 NAVER Cloud `CLOVA Speech`를 수업마다 고를 수 있고, 공유 소리와 파일 변환은 계속 로컬 Qwen을 사용합니다. 완료된 받아쓰기는 선택할 때만 충북대 NOVA Gateway의 `solar-pro4`로 별도 후보정본을 만들 수 있습니다. 화면만 GitHub Pages에 공개되고 로그인·원문 기록·보존 WAV는 WSL이 실행되는 이 컴퓨터가 관리합니다.

사용할 주소와 현재 준비 상태는 다음과 같습니다.

- 저장소: <https://github.com/superwonso/stt_server_cdh>
- 웹 화면: <https://superwonso.github.io/stt_server_cdh/>
- API: 수업 때마다 새로 만들어지는 `https://….trycloudflare.com`
- 계정: 관리자에게 요청
- **확인 완료:** GitHub Pages 배포, Quick Tunnel 외부 `/health`, Pages CORS, 허용하지 않은 웹 출처 차단
- **사용자 작업 필요:** 관리자 화면의 실제 외부 브라우저 확인, 학교 Wi-Fi·태블릿·수업 음성 시험

실시간 입력의 영속 대기열·무기한 재전송·입력 재연결·탭 간 잠금과 CLOVA 선택 변경은 2026-09-04 전체 자동 회귀를 통과했습니다. 실제 브라우저·학교 Wi-Fi·교실 음성 및 CLOVA 실계정 검증 범위는 아래에서 별도로 구분합니다.

현재 방식은 단어마다 바로 바뀌는 자막이 아닙니다. 실시간 입력과 파일 변환 모두 새 음성을 최소 약 8초 모으고 말이 잠시 멈춘 지점에서 자르되, 최대 15초 WAV와 이전 3초 겹침을 사용합니다. Qwen은 강제 정렬의 단어 시각과 0.6초 안정 구간으로 각 겹침의 저장 범위를 나눕니다. CLOVA도 같은 브라우저 청크 주기를 사용하므로 공식 서비스가 스트리밍을 지원하더라도 이 화면의 갱신 주기는 약 8~15초입니다. 실제 수업에서 모든 말을 수학적으로 정확히 한 번씩 저장한다고 보장하지는 않습니다.

## 구조와 개인정보

```text
노트북/태블릿 브라우저
  ├─ 웹 화면 ───────────────────────────── GitHub Pages
  ├─ 마이크/공유 탭 소리의 겹친 WAV ─┐
  └─ 녹음 파일의 재개 가능 조각 ─────┴─ Cloudflare Quick Tunnel ─ 127.0.0.1 FastAPI
                                                                    ├─ ROCm Qwen3-ASR
                                                                    ├─ .data/classroom.sqlite3
                                                                    ├─ .data/imports/* (변환 중만)
                                                                    └─ .data/recordings/* (계정별 WAV)
완료된 수업에서 사용자가 후보정 선택
  └─ FastAPI ── 받아쓴 텍스트만 HTTPS ── 충북대 NOVA Gateway ── solar-pro4

마이크 수업에서 사용자가 CLOVA 선택
  └─ FastAPI ── 16 kHz PCM과 인식 결과 ── NAVER Cloud CLOVA Speech gRPC
```

- 브라우저에서 받은 음성은 Cloudflare를 경유해 이 PC로 전송됩니다. Cloudflare가 HTTPS를 종단하는 구조이므로 Cloudflare를 통하지 않는 종단간 암호화라고 표현하면 안 됩니다.
- 새로 처리한 마이크·공유 소리·가져온 파일의 음성은 겹친 구간을 한 번만 남긴 **16 kHz 모노 PCM WAV**로 `.data/recordings/`의 계정별 `0700` 폴더에 `0600` 권한으로 보관합니다. 업로드한 영상·오디오 원본과 원래 파일명은 보존하지 않습니다. 이 기능을 추가하기 전에 만든 수업의 음성은 이미 폐기되어 복구하거나 내려받을 수 없습니다.
- 녹음 파일 가져오기의 원본은 전송 재개와 서버 디코딩을 위해 `.data/imports/`에 임시 저장합니다. 완료·취소·실패 때 삭제를 확인하고, 실패하면 상태에 그대로 표시한 채 실행 중인 서버가 재시도합니다. 7일간 끝내지 않은 업로드도 자동 폐기합니다.
- 비밀번호는 Argon2 해시로, 로그인 세션과 초대 코드는 해시로 저장합니다. 로그인 토큰은 브라우저 메모리에만 두므로 탭을 닫으면 사라집니다.
- 서버가 아직 확인하지 않은 실시간 WAV 조각은 같은 GitHub Pages 출처의 IndexedDB에 임시 저장하고, 서버 ACK 뒤 해당 조각을 삭제합니다. 새로고침이나 브라우저 재실행 뒤에도 같은 계정으로 로그인하면 남은 순서를 복구할 수 있으며, 복구 시에는 전체 WAV를 한꺼번에 메모리에 올리지 않고 전송할 조각 하나씩 읽습니다. 이 큐에는 비밀번호·로그인 토큰·초대 코드·API 주소를 저장하지 않습니다. 다만 마지막으로 익명 확인한 API 주소는 기존 자동 연결 기능을 위해 별도의 `localStorage`에만 저장됩니다.
- 비공개 로그인 ID 목록과 관리자로 지정한 ID는 Git에서 제외된 `server/.env`와 로컬 DB에만 둡니다. 공개 예시의 `ACCOUNT_USERNAMES`와 `ADMIN_USERNAME`은 의도적으로 비어 있으며, 계정 설정이 없거나 기존 DB와 다르면 서버는 계정을 임의로 추가하지 않고 시작을 중단합니다. 계정 추가는 이 PC의 명시적인 `add-account` 관리 명령으로만 허용됩니다. 관리자 설정이 없거나 구성된 계정 중 하나와 정확히 일치하지 않으면 관리자 API만 닫힌 상태로 유지됩니다.
- `MINDLOGIC_API_KEY`도 Git에서 제외된 권한 `0600`의 `server/.env`에서 서버만 읽습니다. 프런트엔드, API 응답, GitHub Pages 설정에는 키를 넣지 않으며 서버는 키를 문서화된 `https://factchat-cloud.mindlogic.ai/v1/gateway`에만 보낼 수 있도록 목적지를 고정합니다.
- `CLOVA_SPEECH_SECRET_KEY`도 같은 비공개 파일에서 서버만 읽습니다. 프런트엔드에는 설정 가능 여부만 전달하고 키·gRPC 진단·세션 정보는 보내지 않습니다. 목적지는 공식 `clovaspeech-gw.ncloud.com:50051` TLS 주소로 코드에 고정하며 환경변수로 바꿀 수 없습니다.
- 사용자가 마이크 수업에서 CLOVA를 명시적으로 고르면 음성이 `브라우저 → Cloudflare → 이 PC → NAVER Cloud`로 전달됩니다. 스트리밍 인식 결과는 해당 CLOVA 도메인의 고객 Object Storage에 자동 저장됩니다. 이 앱에서 수업을 지우면 이 PC의 DB와 WAV는 삭제하지만 그 클라우드 사본까지 삭제하지는 않으므로 NAVER Cloud 콘솔에서 별도로 관리해야 합니다. Qwen을 고르면 이 외부 음성 인식 전송은 없습니다. [CLOVA 실시간 API](https://api.ncloud-docs.com/docs/ai-application-service-clovaspeech-grpc), [스트리밍 인식 빌더](https://guide.ncloud-docs.com/docs/clovaspeech-builder-streaming)
- AI 후보정은 완료된 수업에서 사용자가 버튼을 누를 때만 실행합니다. NOVA에는 음성·수업 제목·계정 ID가 아니라 받아쓴 구간 텍스트, 언어, 내부 구간 ID가 전송됩니다. 이 PC가 모든 아라비아 숫자와 형식을 인식한 일부 이메일·전화번호·주민번호·카드번호를 먼저 임시 표식으로 바꾸고, 표식이나 기존 숫자가 손상된 응답은 저장하지 않습니다. 정규식 가림은 이름이나 모든 개인정보 형식을 찾는 완전한 익명화가 아니므로 민감한 수업에는 후보정을 누르지 마세요.
- 원문 `segments`는 후보정으로 수정하지 않습니다. 후보정본은 별도 DB 행에 저장하고 화면도 항상 원문으로 먼저 엽니다. 외부 모델이 정보를 잘못 고칠 수 있으므로 `확인 필요` 용어와 숫자 표기 경고를 원문·녹음과 비교하세요. Gateway 호출은 NOVA 크레딧을 사용하며 소진되어도 로컬 원문과 WAV에는 영향이 없습니다. [NOVA Gateway 개요](https://docs.mindlogic.ai/docs/cbnu-ac/api-gateway/getting-started/overview), [Chat Completions](https://docs.mindlogic.ai/docs/cbnu-ac/api-gateway/reference/chat-completions)
- 모든 수업 조회·업로드·녹음 다운로드 티켓 발급·삭제에 서버 측 소유권 검사를 적용합니다. 다운로드 주소에는 로그인 토큰을 넣지 않고, 인증 후 발급한 60초짜리 녹음 전용 주소만 사용합니다. Wi-Fi가 잠깐 끊긴 Range 재개를 위해 유효 시간 안에서 최대 16회만 사용할 수 있습니다.
- 웹 코드에는 계정 목록, 비밀번호, 초대 코드가 없습니다. 현재 Quick Tunnel 주소만 GitHub Pages의 공개 런타임 설정에 게시되므로 페이지를 연 누구나 그 주소는 볼 수 있습니다. 주소 자체를 비밀로 삼지 않고 로그인 제한·비밀번호 검증·서버 측 소유권 검사를 보안 경계로 사용합니다.
- GitHub Pages의 같은 계정 아래 프로젝트들은 하나의 웹 출처를 공유합니다. 따라서 이 앱을 쓰는 동안 같은 출처의 다른 Pages 저장소도 신뢰할 수 있어야 하며, 그 스크립트는 원칙적으로 이 앱의 IndexedDB에도 접근할 수 있습니다. 강한 출처 격리가 필요하면 향후 전용 Pages 계정이나 전용 도메인으로 옮겨야 합니다.
- 영속 대기열은 브라우저 저장공간 quota의 영향을 받습니다. 앱은 persistent storage를 요청하고 사용량을 표시하지만, 기기 저장공간 부족·사용자 데이터 삭제·브라우저 정책으로 보존이 실패할 수 있습니다. 서버 지연 중에는 대기 WAV가 계속 늘므로 수업 전에 여유 공간과 큐 경고를 확인하세요.
- `.data/`, `server/.env`, `.models/`, `.samples/`, 지원하는 음성·영상 컨테이너 확장자, 로그는 `.gitignore`에 포함됩니다. 그래도 푸시 전 `git status`에서 개인 파일이 없는지 반드시 확인하세요. `git add -f`로 강제로 추가하지 마세요.

## 이 PC에서 처음 한 번 설치

확인된 대상 환경은 Ubuntu 24.04 WSL2, Radeon 8060S(gfx1151), ROCm 7.2.4와 `$HOME/miniconda3/envs/torch-rocm`입니다. 다른 PC에서는 Python 경로와 ROCm 호환성을 별도로 확인해야 합니다.

```bash
cd "$HOME/stt_server"
chmod +x scripts/*.sh
./scripts/setup.sh
install -m 600 server/env.example server/.env
```

`server/.env`를 이 컴퓨터에서만 열어 `ACCOUNT_USERNAMES`에 쉼표로 구분한 2~10개의 로그인 ID를 입력하세요. ID는 소문자 영문·숫자·점·밑줄·하이픈으로 된 1~32자여야 하며 서로 달라야 합니다. 운영 중 계정을 늘릴 때는 이 값을 직접 고치지 말고 아래의 `add-account` 절차를 사용하세요. AI 후보정을 쓸 때는 같은 파일의 `MINDLOGIC_API_KEY`에 NOVA Gateway 키를 넣고, `MINDLOGIC_BASE_URL`과 `MINDLOGIC_MODEL=solar-pro4`는 예시값 그대로 둡니다. 실제 값이 든 파일은 커밋하거나 다른 곳에 공유하지 마세요.

CLOVA를 쓸 때는 **Basic 스트리밍/장문 인식 도메인에서 확인한 Secret Key**를 다음 대화형 명령으로 저장합니다. 일반 NCP Access Key가 아니며 `Bearer ` 접두사는 붙이지 않습니다. 입력 문자는 화면이나 셸 기록에 나타나지 않습니다.

```bash
./.venv/bin/python -m server.manage configure-clova
./scripts/stop.sh --server-only
./scripts/start-server.sh
```

이 명령은 키의 형식과 비공개 저장만 확인하며 실제 NAVER 인증이나 음성 인식 성공까지 시험하지는 않습니다. 첫 배포 전에는 비개인 음성으로 연속 두 청크, 무음, 일시정지·재개, 4분 연결 교체를 먼저 검증하세요. 같은 한국어 구간을 Qwen과 비교하기 전에는 CLOVA가 더 정확하다고 가정하지 마세요.

실시간 gRPC는 Free 도메인에서 지원되지 않습니다. Basic 음성 인식 Stream은 15초 단위 5원(VAT 별도)이므로 연속 1시간은 단순 계산 약 1,200원이며, 재전송·겹침·Object Storage 비용은 별도로 늘 수 있습니다. 최신 요금은 [NAVER Cloud 공식 요금표](https://www.ncloud.com/charge/price/ko)에서 다시 확인하세요.

`setup.sh`는 기존 ROCm Python을 재사용하는 `.venv`를 만들고 서버 패키지, 약 6.1 GiB의 Qwen3-ASR·강제 정렬기, 로컬 `cloudflared` 실행 파일을 준비합니다. 검증한 모델 revision과 cloudflared 2026.8.3의 공식 SHA-256을 고정하며, 시스템 ROCm 환경을 덮어쓰지 않습니다. ROCm Python 위치가 바뀌었다면 다음처럼 지정합니다.

```bash
./scripts/setup.sh --python /실제/rocm/python/경로
```

이미 잘못 만든 `.venv`를 교체해야 할 때만 `--recreate-venv`를 사용합니다. 기존 환경은 `.data/venv-backup-*`으로 옮겨 보존됩니다.

GPU가 보이는지 확인하려면 다음을 실행합니다.

```bash
./.venv/bin/python -c "import torch; print(torch.__version__, torch.version.hip, torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else '')"
```

마지막 값이 `False`이면 서버를 시작하지 말고 WSL의 `/dev/dxg`, ROCm 설치, 사용 중인 Python 경로부터 확인하세요.

## GitHub Pages 배포

저장소의 `main` 브랜치에 푸시하면 `.github/workflows/pages.yml`이 `web/`의 공개 파일을 격리된 staging 폴더에 복사하고, 여기에 런타임 `config.json` 하나만 생성해 Pages 아티팩트로 배포합니다. GitHub 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택하고, Actions의 `Deploy classroom to GitHub Pages` 작업이 성공했는지 확인합니다.

저장소 안의 `web/config.json`은 계속 빈 설정으로 두는 것이 정상입니다. `start-tunnel.sh`가 현재 Quick Tunnel 주소와 공개 상태·게시/만료 시각만 GitHub Actions 저장소 변수에 넣고 새 Pages 배포를 요청하며, 워크플로가 이를 24시간짜리 런타임 `config.json`으로 만듭니다. 따라서 주소가 커밋 기록에 남지 않고 일반 코드 배포도 원래 만료 시각을 임의로 연장하지 않습니다. 계정 ID나 인증 정보는 이 과정에서 읽거나 게시하지 않습니다.

자동 게시에는 이 저장소에 접근할 수 있도록 로그인된 GitHub CLI가 필요합니다. 이 컴퓨터에서는 PATH의 `gh` 또는 Git에서 제외된 `.tools/gh-*/bin/gh`를 자동으로 찾습니다. 인증 상태는 실제 토큰을 출력하지 않는 다음 명령으로 확인할 수 있습니다.

```bash
.tools/gh-2.99.0/bin/gh auth status
```

배포 후 <https://superwonso.github.io/stt_server_cdh/>를 열면 브라우저가 같은 출처의 설정을 읽고, 로그인 정보 없이 `/health`를 확인한 뒤 서버 주소를 자동 적용합니다. 저장된 예전 주소보다 새 배포 설정을 우선하며, 설정이 오프라인·만료·잘못된 상태이면 로그인 정보를 전송하지 않습니다. 상단 **내 서버** 입력창은 자동 게시 장애 때만 사용하는 수동 복구 수단입니다.

GitHub에 올리기 전에는 최소한 다음을 확인합니다.

```bash
git status --short
git check-ignore server/.env .data/classroom.sqlite3 .data/invitations.txt .models/Qwen3-ASR-1.7B
```

두 번째 명령에 네 경로가 모두 표시되어야 합니다. 저장소 인증용 토큰도 파일이나 셸 스크립트에 적지 마세요.

## 계정의 첫 비밀번호 설정

초대 링크는 Quick Tunnel 주소가 만들어진 뒤 생성합니다. 먼저 서버와 터널을 실행합니다.

```bash
cd "$HOME/stt_server"
./scripts/start-server.sh
./scripts/start-tunnel.sh
./scripts/status.sh
```

`start-tunnel.sh`가 **GitHub Pages 자동 서버 연결 설정이 준비됐습니다**라고 표시하는지 확인합니다. `status.sh`가 보여 준 `https://….trycloudflare.com` 주소는 아래의 로컬 관리 명령에만 넣습니다.

```bash
./.venv/bin/python -m server.manage init \
  --site-url https://superwonso.github.io/stt_server_cdh/ \
  --api-url https://여기에-현재주소.trycloudflare.com
```

이 명령은 다음 작업만 합니다.

- 아직 비밀번호가 없는 계정마다 7일 유효한 일회용 초대 코드를 새로 만듭니다.
- 원문 링크와 현재 서버 주소는 Git에서 제외된 `.data/invitations.txt`에만 기록합니다.
- **초대 링크에는 서버 주소를 넣지 않습니다.** 위조된 링크가 초대 코드와 새 비밀번호를 공격자 서버로 보내지 못하게 하기 위한 조치입니다.
- Pages 출처를 `server/.env`에 반영합니다. 자주 바뀌는 API 주소는 초대 링크나 서버 설정에 결합하지 않습니다.
- 이미 활성화된 계정의 비밀번호는 바꾸지 않습니다.

링크나 코드가 출력되지 않는 안전한 상태 확인은 `./.venv/bin/python -m server.manage status`로 할 수 있습니다.

출처 설정을 적용하려면 API 서버만 다시 시작합니다. 터널은 그대로 유지합니다.

```bash
./scripts/stop.sh --server-only
./scripts/start-server.sh
```

이 PC에서 `.data/invitations.txt`를 열고 각 사람에게 본인에게만 해당하는 Pages 초대 링크만 직접 전달합니다. 현재 서버 주소는 페이지가 자동으로 찾습니다.

링크를 받은 사람은 서버를 켜고 자동 게시까지 끝난 뒤 본인 초대 링크를 엽니다. 화면에 **현재 서버를 자동으로 찾아 연결을 확인했어요**가 표시되면 4자 이상의 새 비밀번호를 두 번 입력합니다. 4자도 허용하지만 공개된 로그인 주소를 상대로 추측하기 쉬우므로 가능하면 훨씬 더 길게 정하고, 4자리 숫자·흔한 단어는 피하세요. 브라우저는 초대 링크의 `username`과 `setup_code`만 복원하며, 링크에 `api=`가 위조돼 있어도 무시합니다. 성공한 링크는 다시 사용할 수 없습니다. 초대받은 사용자의 설정이 끝나면 초대 파일은 이 PC 밖으로 백업하지 말고 보관하거나 직접 삭제하세요.

한 사람만 설정하기 전에 터널 주소가 바뀌어도 초대 링크는 그대로 사용할 수 있습니다. 새 터널을 시작해 Pages 자동 게시만 완료하면 되며 `init`을 다시 실행할 필요가 없습니다. `init`을 다시 실행하면 아직 활성화되지 않은 계정의 초대 코드가 새것으로 교체되어 이전 링크가 무효가 됩니다.

### 운영 중 계정 추가

기존 계정이 있는 DB에 새 계정을 넣을 때는 서버를 잠시 멈추고 먼저 백업한 뒤, 새 ID가 셸 기록이나 화면에 나타나지 않는 대화형 명령을 사용합니다. `ACCOUNT_USERNAMES`를 직접 수정하면 DB와 불일치하므로 서버가 안전하게 시작을 거부합니다.

```bash
cd "$HOME/stt_server"
./scripts/stop.sh --server-only
./scripts/backup.sh .data/backups/pre-account-add-YYYYMMDD.sqlite3
./.venv/bin/python -m server.manage add-account
```

프롬프트에 새 ID를 입력해도 문자는 보이지 않습니다. 이 명령은 기존 목록의 순서와 관리자 지정, 비밀번호, 세션, 수업을 유지하면서 비활성 계정 한 개만 `server/.env`와 DB에 함께 추가합니다. 그다음 서버와 터널을 켜고 위의 `server.manage init`을 실행하면 새 미활성 계정의 일회용 링크만 `.data/invitations.txt`에 생성됩니다. 기존 활성 계정의 비밀번호는 바뀌지 않습니다.

## 관리자 페이지

구성된 활성 계정 중 하나를 관리자로 지정하려면 이 PC의 대화형 WSL 터미널에서 한 번 실행합니다.

```bash
cd "$HOME/stt_server"
./.venv/bin/python -m server.manage configure-admin
./scripts/stop.sh --server-only
./scripts/start-server.sh
```

비밀번호가 설정된 계정이 하나뿐이면 그 계정을 선택합니다. 여러 계정이 활성화된 경우 관리자로 쓸 ID를 묻지만 입력 문자는 화면과 셸 기록에 표시하지 않습니다. 실제 ID를 입력하지 않고 `ACCOUNT_USERNAMES` 순서로 고르려면 명령 끝에 `--position 1`처럼 1~10 위치를 붙여도 됩니다. 자동으로 어느 계정인지 추정하지 않으며, 선택한 ID는 Git에서 제외된 권한 `0600`의 `server/.env`에만 `ADMIN_USERNAME`으로 저장됩니다. 새 계정을 추가해도 기존 관리자 지정은 바뀌지 않습니다.

관리자 계정으로 로그인하면 **관리자** 화면이 나타납니다. 여기서 다음을 확인하거나 조작할 수 있습니다.

- 서버 가동 시간, 모델 상태, CPU load, RAM·서버 프로세스 메모리, 디스크와 사용 가능한 GPU 메모리
- 각 계정의 활성화 여부, 현재 접속 여부와 `기록 중·업로드 중·변환 중·후보정 중·자리 비움` 같은 최소 활동 상태, 활성 세션 수와 작업 대기열
- 최근 운영 접속 변경, 터널 재연결, 다른 계정 세션 종료 조작 이력
- 새 수업·조회·업로드 요청을 받지 않는 **운영 일시중지**와 다시 열기
- Cloudflare Quick Tunnel이 끊겼거나 불안정할 때의 **터널 재연결**

활동 상태는 로그인된 브라우저가 15초마다 보내는 짧은 상태값이며 45초 동안 새 신호가 없으면 오프라인으로 표시됩니다. IP 주소, 기기·브라우저 정보, 수업 제목·ID, 음성, 받아쓴 본문은 관리자 상태용으로 수집하지 않고 상태값도 DB에 저장하지 않습니다. 관리자 API는 서버에서 `ADMIN_USERNAME`을 다시 검사하므로 화면 요소를 숨기는 것에 권한을 의존하지 않습니다. 일반 계정이 관리자 주소를 직접 요청해도 거절됩니다.

**운영 일시중지**는 원격 관리 연결과 로그인은 남겨 두고 이후의 수업 데이터 요청을 `503`으로 막습니다. 서버가 이미 받아 처리 중인 한 건의 전사와 이미 대기열에 들어간 파일 변환·후보정은 중간에 강제 종료하지 않지만, 실시간 녹음의 다음 음성 조각은 접속을 다시 열 때까지 재시도해야 합니다. 반대로 Cloudflare 프로세스를 완전히 끄면 그 터널을 통해 다시 켤 원격 경로도 함께 사라집니다. 그래서 관리자 화면에는 물리적 터널 종료 대신 안전한 일시중지와 재연결만 제공합니다. 터널을 완전히 끈 뒤 다시 시작하는 작업은 이 PC의 WSL에서 `./scripts/start-tunnel.sh`를 실행해야 합니다.

## 수업 전 켜기

수업 시작 10분 전 WSL 터미널에서 다음 세 줄을 실행하는 것을 권장합니다.

```bash
cd "$HOME/stt_server"
./scripts/start-server.sh
./scripts/start-tunnel.sh
./scripts/status.sh
```

`start-server.sh`는 모델을 미리 불러오고 첫 추론 경로를 준비합니다. 첫 준비는 몇 분 걸릴 수 있으며 최대 10분을 기다립니다. 터널은 로컬 서버가 정상일 때만 시작합니다. `start-tunnel.sh`는 외부 health를 확인한 뒤 GitHub Pages 설정까지 게시하고, 배포가 확인될 때까지 진행 상황을 표시합니다. 게시만 실패하면 터널은 사용할 수 있게 남겨 두고 오류로 끝나므로 GitHub 로그인을 고친 뒤 같은 명령을 다시 실행하면 됩니다.

그다음 사용자 기기에서 다음 순서로 확인합니다.

1. <https://superwonso.github.io/stt_server_cdh/>를 엽니다.
2. **현재 서버를 자동으로 찾아 연결을 확인했어요** 표시를 확인합니다. 주소를 따로 입력할 필요는 없습니다.
3. 본인 아이디와 비밀번호로 로그인합니다.
4. 새 수업 이름과 언어를 고릅니다.
5. 아래의 마이크·컴퓨터 소리·녹음 파일 중 원하는 입력을 사용합니다.

### 마이크로 실시간 받아쓰기

**실시간 입력 → 기기 마이크**를 고른 뒤 **마이크 음성 인식**에서 엔진을 선택하고 **받아쓰기 시작**을 누릅니다.

- **이 PC의 Qwen**이 기본값입니다. 음성 인식용 오디오를 NAVER Cloud에 보내지 않고 GPU를 이 PC에서 사용합니다.
- **NAVER CLOVA Speech**는 키가 서버에 설정된 경우에만 선택할 수 있습니다. 수업을 만든 뒤에는 엔진을 바꿀 수 없으며 CLOVA 장애 때 Qwen으로 몰래 전환하지 않습니다.
- CLOVA 연결은 한 수업 동안 문맥을 유지하고 공식 5분 연결 제한 전에 안전한 청크 경계에서 교체합니다. 정상 연결에는 겹침을 다시 보내지 않고, 재연결 때만 직전 최대 3초를 문맥으로 보내 그 구간의 결과는 버립니다.
- CLOVA 요청은 서버로 보내기 전에 해당 조각을 IndexedDB의 `inflight` 상태로 먼저 기록합니다. 응답 전에 탭이나 브라우저가 종료되면 같은 음성의 중복 기록·과금 위험이 있으므로 다음 로그인에서 자동 재전송하지 않습니다. 입력 캡처와 후속 WAV의 로컬 저장은 계속하며, 실패 WAV를 먼저 보관하고 경고를 이해한 경우에만 수동 재전송하세요.

데스크톱 Chrome에서 다른 탭을 잠깐 보는 것만으로 항상 중단되는 것은 아니지만 브라우저·OS 절전 정책에 따라 백그라운드 페이지가 정지될 수 있습니다. 특히 모바일·태블릿에서는 수업 중 화면을 켜고 앱 탭을 전면에 유지하세요. OS가 마이크 캡처 자체를 멈춘 동안의 소리는 나중에 재연결해도 복구할 수 없습니다. live track이 음소거 상태로 오래 남아도 앱은 수업을 종료하거나 입력 그래프를 임의로 닫지 않고 기다리며, 사용자가 **입력 복구 시도**를 누르면 같은 수업에서 입력만 다시 연결합니다. Qwen과 CLOVA의 한국어 정확도는 실제 같은 수업 음성으로 비교한 뒤 선택하는 것이 좋습니다.

### 유튜브·온라인 강의 등 컴퓨터 소리 받아쓰기

데스크톱 Chrome 또는 Edge에서 **실시간 입력 → 컴퓨터·브라우저 탭 소리**를 고르고 **화면 소리 받아쓰기**를 누릅니다. 이 입력은 CLOVA 설정과 관계없이 항상 로컬 Qwen으로 처리합니다. 공유 창에서 재생할 브라우저 탭을 선택하고 **탭 오디오 공유**를 켜는 방식이 가장 예측 가능합니다. 전체 화면을 고를 때 **시스템 오디오 공유**가 보이면 켤 수 있습니다.

- 브라우저의 화면 공유 API는 사용자가 매번 화면/탭을 직접 골라야 하고, 오디오 제공 여부도 브라우저와 선택한 표면에 따라 달라집니다. 오디오 없는 표면을 고르면 앱이 중단하고 다시 안내합니다. [MDN `getDisplayMedia`](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [W3C Screen Capture](https://www.w3.org/TR/screen-capture/)
- API 규칙상 영상 선택도 필요하지만 앱은 반환된 **오디오 트랙만** AudioWorklet에 연결합니다. 영상 프레임은 인코딩·네트워크 전송·저장하지 않습니다.
- 공유 범위에 포함된 알림과 다른 앱의 사적인 소리도 들어갈 수 있습니다. 알림을 끄고 공유 범위를 확인하세요. DRM 보호 영상, 일부 강의 플랫폼, Safari/Firefox, 태블릿에서는 오디오 트랙을 주지 않거나 캡처를 막을 수 있습니다.
- 일시적인 `mute`나 AudioContext `suspended`/`interrupted`는 현재 수업을 끝내지 않고 입력 재개를 시도합니다. 사용자가 공유를 중지하거나 track이 영구적으로 `ended`되면 받은 PCM과 대기열은 유지한 채 **입력 다시 연결**을 요구합니다. 중단 중 실제로 캡처되지 않은 소리는 복구되지 않습니다.

### 실시간 입력 일시정지·재개

마이크와 공유 소리 모두 **일시정지**와 **받아쓰기 재개**를 사용할 수 있습니다. 일시정지는 수업을 끝내지 않습니다. 같은 수업 ID와 누적 음성 시간축을 유지하고, 직전 3초 겹침 문맥도 보존한 채 이어서 기록합니다.

- 일시정지를 누르면 그 경계까지 이미 받은 새 음성을 **비최종 청크**로 정리해 보냅니다. 일시정지 중의 마이크·공유 소리는 브라우저에서 버리며 WAV로 만들거나 서버에 전송·저장하지 않습니다. 기록 시간축에도 정지한 시간만큼의 빈 음성을 만들지 않습니다.
- 재개하면 보존한 3초 문맥 뒤에 새 음성을 붙입니다. 여러 번 일시정지해도 같은 수업으로 이어지고, **받아쓰기 종료**를 눌렀을 때만 마지막 `final` 청크를 보내 남은 문장과 녹음 WAV를 확정합니다.
- 일시정지 경계 뒤 탭이 비정상 종료되어 브라우저의 마지막 `final` 조각을 잃었더라도, 나중에 그 수업의 **녹음 WAV 마무리**를 누르면 서버가 이미 저장한 WAV 끝부분만 다시 확인해 보류된 마지막 문장을 확정합니다. 같은 복구 요청이나 응답 유실은 중복 문장을 만들지 않도록 같은 내부 작업으로 재사용합니다.
- 일시정지 상태는 로그인 세션을 대신하지 않습니다. 세션이 만료되거나 서버가 인증을 거절해도 현재 캡처와 IndexedDB 대기열은 계정 binding을 유지합니다. 반드시 같은 계정으로 다시 로그인해야 전송을 이어갈 수 있고 다른 계정은 그 작업을 가져갈 수 없습니다.
- 재로그인 화면이 떠 있는 동안에도 입력이 계속될 수 있으므로 그 화면의 **이 기기의 녹음 종료** 버튼으로 언제든 캡처를 끝낼 수 있습니다.
- Web Locks를 지원하는 브라우저에서는 계정별 녹음 잠금과 업로드 잠금으로 같은 계정의 두 탭이 동시에 녹음하거나 같은 조각을 함께 보내지 못하게 합니다. 다른 탭이 녹음 중이면 수업 삭제와 녹음 마무리도 시작하지 않고, 녹음 종료 뒤에는 업로드 잠금 안에서 공유 IndexedDB를 다시 확인해 미전송 조각이 하나도 없을 때만 삭제·마무리를 실행합니다. 저장소 장애로 음성이 현재 탭 RAM에만 남은 경우에는 녹음을 끝낸 뒤에도 그 음성을 전송하거나 확인 후 건너뛸 때까지 녹음 잠금을 유지합니다. 지원하지 않는 브라우저에는 경고를 표시하며 탭 간 안전을 보장할 수 없으므로, 한 계정의 실시간 수업은 반드시 한 탭에서만 진행하세요. 비정상 종료 뒤 남은 수업은 자동으로 끝내지 않고 화면에 계속 표시하므로, 다른 탭의 녹음 여부를 확인한 뒤 직접 **녹음 WAV 마무리**를 사용합니다.

### 녹음 파일 올려 변환

**녹음 파일 가져오기**에서 파일을 고르고 수업 이름·언어를 확인한 뒤 **파일 올려 변환**을 누릅니다. WAV, MP3, M4A/AAC, FLAC, OGG/Opus, WebM과 오디오가 든 MP4·MKV·MOV를 표시하지만, 실제 디코딩 가능 여부는 파일 내부 코덱과 [PyAV/FFmpeg](https://pyav.basswood.io/docs/stable/api/audio.html) 지원에 달려 있습니다. 파일은 최대 1 GiB, 디코딩된 음성은 최대 4시간이며 계정마다 동시에 한 작업만 진행합니다.

- 브라우저는 모든 파일 바이트를 480 KiB 이하로 읽어 SHA-256 조각 목록에 묶습니다. 전체 파일을 한꺼번에 메모리에 올리지 않으며, 업로드 조각도 하나씩 보냅니다.
- **업로드 중에는 탭을 닫지 마세요.** 연결이 끊기면 처음 고른 것과 정확히 같은 파일을 다시 골라 받은 위치부터 이어갈 수 있습니다. 서버가 대기/변환 상태가 된 뒤에는 탭을 닫아도 이 PC에서 계속 처리하고, 다음 로그인 때 상태를 복구합니다.
- 파일 원본은 Cloudflare를 경유하며 이 PC의 `.data/imports/`에만 임시 저장됩니다. 완료·취소·실패 화면의 “원본 임시 파일 삭제됨”을 확인하세요. “삭제 재시도 중”이면 서버를 켜 둔 채 잠시 뒤 다시 로그인해 상태를 확인합니다.
- 변환이 완료되면 원본 대신 추출·정규화한 16 kHz 모노 WAV가 수업에 연결되어 남습니다. 따라서 내려받는 WAV는 올린 MP3·영상 등의 원본과 byte-for-byte 같은 파일이 아니며 영상 프레임도 포함하지 않습니다.
- 취소는 현재 최대 15초짜리 모델 추론을 끝낸 뒤 적용될 수 있습니다. 그 사이 먼저 완료되면 앱은 완료로 표시하며 결과를 삭제하지 않습니다.

임시 네트워크 오류와 서버 혼잡은 같은 음성 조각 ID를 유지하고 간격에 상한이 있는 지수 backoff로 횟수 제한 없이 순서대로 재시도합니다. 지연 중에도 입력은 계속 받고 서버가 확인하지 않은 WAV는 IndexedDB에 보존하므로, 8개가 쌓였다는 이유로 녹음을 끝내지 않습니다. 새로고침 뒤에도 같은 계정으로 로그인하면 이어서 보냅니다. 탭 간 업로더 잠금이 있는 브라우저에서는 한 탭만 대기열을 전송합니다. 형식·권한 오류와 `inflight`로 복구된 CLOVA 조각처럼 자동 재전송이 안전하지 않은 조각은 보류하며, **다시 전송** 또는 **실패 WAV 내려받기**와 **파일 저장 확인 · 건너뛰기**를 명시적으로 선택해야 합니다. 건너뛴 구간은 서버 기록에서 빠집니다.

Quick Tunnel 주소가 바뀌면 앱은 GitHub Pages의 새 런타임 설정을 익명 `/health`로 먼저 확인합니다. 새 후보를 확인하는 동안에는 기존에 검증된 서버로 진행 중인 녹음 전송을 계속하되, 기존 로그인 토큰은 새 origin으로 보내지 않습니다. 새 주소가 설치되면 녹음·대기 WAV를 유지한 채 같은 계정으로 다시 로그인해야 그 주소에서 전송을 재개합니다.

실시간 수업을 끝낼 때 **받아쓰기 종료**를 누르고, 마지막 `final` 청크의 처리 대기 표시가 사라지고 **서버 컴퓨터에 저장됨**이 나온 뒤 내보내기나 녹음 다운로드를 사용합니다. 입력 종료 확인이 실패하면 **마지막 오디오 일부 누락 가능 · 받은 내용만 저장됨** 경고가 다음 녹음 전까지 남습니다. 이 경우 내려받은 텍스트와 WAV의 끝부분을 직접 확인하세요.

### 지난 수업 보기·내보내기·삭제

- 지난 수업은 한국 시간(`Asia/Seoul`) 날짜별로 묶입니다. **전체 날짜** 또는 원하는 날짜를 골라 볼 수 있습니다.
- 수업을 연 뒤 형식을 고르고 **내보내기**를 누르면 현재 화면에서 선택한 원문 또는 후보정본을 UTF-8 `.txt`로, 혹은 제목·날짜·언어·타임스탬프가 포함된 `.md`로 저장합니다. 후보정본 파일명에는 `_AI후보정`이 붙습니다.
- 새 기능 적용 뒤 정상적으로 끝난 수업은 **녹음 WAV**로 내려받을 수 있습니다. 서버 재시작이나 마지막 실패 조각 건너뛰기로 WAV만 미확정 상태라면 같은 버튼이 먼저 **녹음 WAV 마무리**를 수행합니다. 녹음·변환 중이거나 기능 적용 전이라 저장된 WAV가 없는 수업은 버튼이 비활성화됩니다.
- **수업 삭제**는 확인창을 거쳐 받아쓰기 원문, 후보정본, 청크 정보, 연결된 파일 변환 기록과 보존 WAV를 함께 영구 삭제합니다. 진행 중인 전사·파일 변환·AI 후보정이 있으면 서버가 `409`로 거절하므로 먼저 끝내거나 취소하세요. 삭제한 내용은 앱에서 복구할 수 없지만, 삭제 전에 만든 별도 백업에는 남아 있을 수 있습니다.
- WAV는 시간당 약 110 MiB입니다. 기본 보존 한도는 전체 20 GiB이고, 디스크에 최소 1 GiB를 남깁니다. 필요하면 ignored `server/.env`의 `MAX_RECORDINGS_BYTES`와 `RECORDING_FREE_RESERVE_BYTES`를 조정하세요.

### 받아쓰기 AI 후보정

완료된 수업에서는 **AI 후보정 만들기**를 누릅니다. 진행 중인 수업에서 이 버튼을 눌러도 마이크나 공유 소리를 즉시 멈추지 않고 후보정만 예약합니다. 사용자가 나중에 **받아쓰기 종료**를 누르고 마지막 `final` 청크까지 서버에 저장되면, 그때 확정된 원문으로 후보정을 자동 시작합니다. 마지막 저장이 실패한 상태에서는 불완전한 원문을 보내지 않습니다.

- 원문은 자동으로 바뀌지 않으며 화면도 항상 **받아쓴 원문**으로 먼저 열립니다. 완료 뒤 **AI 후보정본**을 골라 비교하세요.
- 완료된 과거 수업의 후보정은 다른 수업의 실시간 녹음이나 일시정지 상태와 병행할 수 있습니다. 후보정은 별도 서버 작업으로 실행되며 로컬 음성 인식의 GPU 추론 잠금을 차지하지 않습니다.
- 아직 변하는 실시간 원문을 즉시 후보정하지 않는 이유는 겹침 청크의 확정 구간과 마지막 문장·segment 목록이 종료 전까지 달라질 수 있기 때문입니다. 중간 revision을 보내면 빠진 끝 문장이나 오래된 결과가 생길 수 있으므로 서버는 수업별 `final` 상태와 고정된 원문 revision을 확인합니다.
- 후보정은 문장 ID와 시각을 유지한 채 약 6,000자씩 나누고 앞뒤 문장을 읽기 전용 문맥으로 전달합니다. 겹친 문맥은 출력에 포함하지 않아 같은 문장이 중복 저장되지 않습니다.
- 모델 응답의 문장 ID·개수·순서, 보호 임시 표식, 기존 숫자, 응답 크기를 서버가 확인합니다. 원문의 아라비아 숫자는 전송 전에 임시 표식으로 고정합니다. 숫자가 없던 문장에 새 숫자 표기가 생기면 결과를 버리는 대신 화면에 원문 비교 경고를 표시하고, 기존 숫자가 있던 문장의 숫자열이 바뀌거나 추가·삭제되면 후보정본을 저장하지 않습니다.
- `확인 필요` 목록은 모델 판단과 숫자 표기 경고이므로 정답 보장이 아닙니다. 전문용어·고유명사·수식은 원문 및 WAV와 직접 대조하세요.
- 크레딧 소진, 인증 오류, 잘못된 응답, 일시적인 Gateway 장애는 후보정만 실패시킵니다. 원문과 WAV는 그대로 남고, 문제를 해결한 뒤 같은 버튼으로 다시 요청할 수 있습니다.

## 종료

실시간 수업의 전송과 파일 업로드가 끝난 것을 웹 화면에서 확인한 뒤 실행합니다. 파일이 이미 **서버 변환 대기/변환 중**이라면 정상 종료 시 완료한 청크 ID를 보존하고 작업을 대기로 돌리므로 다음 서버 시작 때 이어서 처리합니다. AI 후보정도 문장 묶음 사이에서 종료 신호를 확인하고 미완료 작업을 다음 시작 때 다시 대기시킵니다. 외부 요청 응답을 기다리다 강제 종료되면 같은 묶음이 재전송되어 크레딧이 다시 들 수 있으므로, 가능하면 후보정 완료 뒤 종료하세요. 그래도 종료 직전에는 가능하면 변환 완료와 원본 삭제 표시까지 기다리는 편이 안전합니다.

```bash
cd "$HOME/stt_server"
./scripts/stop.sh
./scripts/status.sh
```

종료 스크립트는 외부 터널을 먼저 닫고 API 서버를 정상 종료한 뒤 Pages 설정을 오프라인으로 바꾸는 배포를 짧게 요청합니다. GitHub가 일시적으로 응답하지 않아 오프라인 게시가 실패해도 로컬 종료 결과는 유지되며, 브라우저의 익명 health 확인이 죽은 주소로 로그인 정보를 보내지 않게 막습니다. 종료 후 기존 텍스트 기록과 아직 끝나지 않은 파일 작업 상태는 `.data/`에 남습니다.

## 백업

SQLite WAL에 남아 있는 최신 기록까지 일관되게 포함하려면 DB 파일을 직접 복사하지 말고 다음 명령을 사용합니다. 서버 실행 중에도 SQLite의 온라인 백업 기능으로 스냅샷을 만들 수 있으며, 기존 대상 파일은 덮어쓰지 않습니다.

```bash
./scripts/backup.sh /암호화된/개인저장소/classroom-$(date +%Y%m%d).sqlite3
```

이 명령은 **DB만 백업하며 `.data/recordings/`의 WAV는 포함하지 않습니다.** 음성까지 함께 보존하려면 먼저 `./scripts/stop.sh`로 전송과 변환을 정상 종료한 다음, 생성한 SQLite 백업과 `.data/recordings/` 폴더를 같은 암호화된 개인 저장소에 함께 복사하세요. 복원할 때도 둘을 같은 시점의 묶음으로 되돌려야 합니다.

백업에는 모든 계정의 비밀번호 해시, 개인 수업 텍스트와 음성이 들어갈 수 있습니다. GitHub, 공유 Drive, 메신저에 원본 그대로 올리지 마세요. 앱에서 수업을 삭제해도 먼저 만든 백업에서는 자동으로 지워지지 않습니다.

## 문제 해결

### 서버가 준비되지 않음

```bash
./scripts/status.sh
tail -n 80 .data/server.log
```

`ROCm GPU is not visible`이면 ROCm Python과 `/dev/dxg`를 확인합니다. `ASR model is incomplete`이면 `./scripts/setup.sh`를 다시 실행합니다. 프로세스가 살아 있지만 준비가 늦다면 모델 다운로드 또는 warmup이 끝날 때까지 로그를 확인합니다.

### 외부에서 연결되지 않음

```bash
tail -n 80 .data/tunnel.log
./scripts/start-tunnel.sh
```

Quick Tunnel을 다시 시작하면 주소가 바뀌지만 정상적으로는 새 주소가 Pages에 자동 반영되므로 직접 교체하지 않습니다. `start-tunnel.sh`가 자동 게시 오류로 끝났다면 다음을 확인한 뒤 명령을 다시 실행하세요. 이미 정상인 터널은 종료하지 않고 게시만 다시 시도합니다.

```bash
.tools/gh-2.99.0/bin/gh auth status
./scripts/start-tunnel.sh
```

그래도 게시할 수 없을 때만 `status.sh`의 현재 주소를 상단 **내 서버**에 직접 입력합니다. 자동 설정에는 24시간 만료와 익명 health 검사가 있으므로, 오래된 주소만 남아 있으면 로그인 버튼이 열리지 않습니다. Cloudflare의 [Quick Tunnel 공식 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)도 이를 테스트·개발용 기능으로 설명하므로, 중요한 수업 전에는 반드시 학교 네트워크의 실제 기기에서 연결 표시와 짧은 받아쓰기를 확인하세요.

전송 대기 음성이 남은 상태에서 주소가 바뀌어도, 현재 전송 시도가 끝난 뒤 **내 서버**에서 새 주소를 확인할 수 있습니다. 앱은 대기 WAV와 조각 ID, 기존 사용자를 메모리에 유지합니다. 반드시 같은 계정으로 다시 로그인하면 새 터널을 통해 이어서 전송합니다. 다른 계정은 남은 큐를 가져갈 수 없습니다.

### “허용되지 않은 사이트”가 표시됨

`server/.env`의 `SITE_ORIGINS`가 다음과 같은 정확한 Pages 출처인지 확인합니다.

```dotenv
SITE_ORIGINS=https://superwonso.github.io
```

수정 후 `./scripts/stop.sh --server-only`와 `./scripts/start-server.sh`로 API를 다시 시작합니다. 저장소 경로 `/stt_server_cdh/`는 URL 출처에 포함하지 않습니다.

### 로그인이 되지 않음

- 초대 링크는 7일, 1회만 유효합니다.
- 새 비밀번호는 4~128자입니다. 가능하면 더 길게 정하고 4자리 숫자·흔한 단어는 피하세요.
- 반복 실패에는 IP·IP+계정 기준 5분 제한과, 여러 주소를 합산한 계정별 30분 창(최대 50회)이 적용됩니다.
- Quick Tunnel 주소가 달라졌다면 `./scripts/start-tunnel.sh`를 다시 실행해 자동 게시를 확인하세요. 자동 게시를 끝내 고칠 수 없을 때만 **내 서버**에 현재 주소를 직접 입력합니다.

### 받아쓰기 지연 또는 전송 대기

이 앱은 단일 GPU 추론을 직렬화합니다. 여러 사용자가 동시에 말하면 한 요청이 오래 대기할 수 있습니다. `429`, 일시적인 `503`, 네트워크·터널 지연은 동일 UUID로 상한이 있는 지수 backoff를 적용해 횟수 제한 없이 순서대로 재시도합니다. 그동안 녹음을 멈추지 않고 미확인 WAV를 IndexedDB에 쌓으므로 상태 표시와 브라우저 저장공간을 확인하세요. 서버 ACK를 받으면 해당 로컬 조각을 삭제합니다.

새 Quick Tunnel을 자동 발견했을 때에는 보안을 위해 기존 token을 새 origin에 보내지 않습니다. 같은 계정으로 다시 로그인하면 보존된 큐가 이어집니다. 형식·권한 오류와 모호한 CLOVA 결과는 무기한 자동 재시도 대상이 아니므로 화면의 수동 복구 안내를 따르세요.

CLOVA 수업은 외부 gRPC 응답을 기다리므로 로컬 GPU 대기와 별개입니다. 선택 항목이 **서버 설정 필요**이면 이 PC에서 `server.manage configure-clova`를 실행하고 API 서버만 재시작하세요. 인증·도메인·네트워크 오류는 안전한 `424` 안내로 바꾸며 공급자 원문이나 키는 화면과 로그에 남기지 않습니다. 응답이 모호한 실패는 자동 재전송하지 않습니다.

### 파일 업로드가 멈추거나 변환되지 않음

- `업로드를 계속하려면`이 보이면 이름만 같은 파일이 아니라 처음의 **동일한 파일 내용**을 다시 고릅니다. 전체 바이트 지문이 다르면 전송 전에 거절합니다.
- 대기/변환 상태는 탭을 닫아도 서버에서 계속됩니다. 다시 로그인하면 자동 복구합니다.
- `지원되는 오디오가 있는 파일` 오류는 확장자와 실제 컨테이너/코덱이 다르거나, 외부 파일을 참조하는 재생목록형 미디어이거나, 오디오 스트림이 없을 때도 표시됩니다.
- `원본 임시 파일 삭제 재시도 중`이면 서버의 파일 권한·디스크 상태를 확인하고 서버를 켜 둡니다. 목록 조회와 백그라운드 정리기가 삭제를 다시 시도합니다.

### AI 후보정이 실패함

- `후보정 API 키가 서버에 설정되지 않았습니다` 또는 `API 인증` 안내가 나오면 `server/.env`의 `MINDLOGIC_API_KEY`에 키 값만 있는지 확인하고 `./scripts/stop.sh --server-only` 다음 `./scripts/start-server.sh`로 다시 시작합니다.
- `크레딧이 부족`하면 [NOVA Gateway 크레딧 조회](https://docs.mindlogic.ai/docs/cbnu-ac/api-gateway/reference/credits)에서 잔여량을 확인합니다. ChatGPT·Gemini 웹 구독과 Gateway 크레딧은 별개입니다.
- `숫자가 바뀐 결과`, `개인정보 보호 표시`, `결과 형식` 오류는 안전 검사로 후보정본을 저장하지 않은 상태입니다. 원문을 사용하고, 같은 오류가 반복되면 `.data/server.log`에는 개인 본문 대신 정제된 오류만 남는다는 전제에서 운영자에게 상태 문구를 알려 주세요.
- 외부 Gateway가 느리거나 끊기면 서버는 제한된 횟수만 재시도합니다. 완료 전에도 원문 내보내기와 WAV 다운로드는 사용할 수 있습니다.

NOVA 키 인증, 현재 모델 목록의 `solar-pro4`, 크레딧 endpoint를 실제 계정으로 확인했습니다. 비개인 한국어 예문을 실제 Chat Completions strict JSON schema로 후보정해 문장 ID·기존 숫자·가린 이메일 복원과 새 숫자 표기 경고까지 통과했습니다. 이 검증은 짧은 합성 텍스트이며 실제 교실 음성에서 Qwen 오류를 얼마나 고치는지, 45~90분 수업의 전문용어·수식·여러 화자를 장문 후보정했을 때 품질과 크레딧 사용량이 어떤지는 아직 확인하지 않았습니다. 실제 수업 샘플과 정답문으로 원문/후보정 CER 및 의미 왜곡을 별도 평가해야 합니다.

격리 API 회귀 테스트에서는 `threading.Event`로 후보정 작업을 멈춰 둔 동안 다른 수업의 청크 전사·녹음 확정이 완료되고, 반대로 음성 인식을 멈춰 둔 동안 과거 수업 후보정이 완료되는 것을 확인했습니다. 양쪽 수업의 원문·후보정본·segment도 섞이지 않았습니다. 이는 서버 잠금과 DB 계약 검증이며 실제 브라우저와 외부 Gateway의 장시간 동시 운용 시험은 아닙니다.

실제 Chrome/Edge와 Quick Tunnel에서 영속 대기열 복구, 새 터널 재로그인, AudioContext 중단과 track 종료 뒤 입력 재연결을 장시간 반복했을 때의 경계 음절, 3초 문맥, 중복, 마지막 청크와 저장공간 증가는 아직 확인하지 않았습니다. 브라우저·OS가 백그라운드에서 캡처 자체를 중단한 동안의 소리는 복구할 수 없고, 첫 입력이 50ms도 쌓이기 전에 페이지 프로세스가 사라진 극히 짧은 PCM도 서버나 IndexedDB에 없을 수 있습니다. 중요한 수업 전에는 사용할 기기와 네트워크에서 짧은 중단·재개·종료 시험을 먼저 하세요.
