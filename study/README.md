# 여백 암기 학습

여백 로그인 후 상단의 **암기 학습** 탭에서 사용합니다. 기본 한능검 문제집과 직접 가져온 문제집으로 학습하기·플래시카드를 제공합니다.

사용자의 최종 선택에 따라 **기존 여백 주소와 GitHub Pages 배포를 유지**합니다. Next.js App Router를 정적 파일로 내보내 같은 출처의 하위 화면에 넣었습니다. 별도 Vercel 서비스·Supabase 계정은 만들지 않았습니다.

## 구성

```text
seed/                         원본 Excel·HTML 참고 자료 (웹 공개 폴더 아님)
study/
  src/app/                    Next.js 페이지·모바일 스타일·next/font
  src/components/             홈·학습·플래시카드·파일 가져오기
  src/lib/                    채점·보기·라운드·저장 어댑터·파일 처리
  scripts/import-xlsx.ts      Excel 검증과 정적 JSON 생성
  data/                       빌드 검증용 문제·단원 데이터
  public/                     기본 문제 데이터·한글 PDF 글꼴
  tests/                      Vitest 단위 검사
  e2e/                        실제 브라우저 학습 흐름
web/study-bridge.js            기존 여백 로그인과 탭 연결
server/study_import.py         선택적 GPT-6 Luna 문제 생성 API
```

## 로컬 실행

Node.js 24와 pnpm 11.25.0을 사용합니다. Python 서버를 켜지 않아도 학습·파일 가져오기·내보내기를 검사할 수 있습니다.

```powershell
cd study
pnpm install --frozen-lockfile
pnpm run build
pnpm run serve
```

브라우저에서 `http://127.0.0.1:3218/__study-test/`를 엽니다. 테스트 호스트는 가상 학습 범위만 제공하며 운영 로그인을 사용하지 않습니다. 테스트 호스트 코드는 배포 산출물에 포함되지 않습니다. `pnpm dev`는 Next 개발용이며 독립 화면에서는 여백 탭에서 열도록 안내합니다.

`.env.example`에 정적 경로를 문서화했습니다. 웹앱에 API 키나 로그인 토큰을 넣지 않습니다. AI 생성은 부모 여백 화면의 기존 인증 연결을 통해서만 요청합니다. `NEXT_PUBLIC_BASE_PATH` 기본값은 `/stt_server_cdh/study`입니다.

## 기본 문제집 갱신

1. `seed/한능검_공부내용확인_문제답.xlsx`를 교체합니다.
2. `study`에서 `pnpm run import`를 실행합니다. (`pnpm import`는 pnpm 자체 명령이므로 사용하지 않습니다.)
3. 출력 개수와 검증 결과를 확인하고 검사·빌드를 실행합니다.

원본의 `문제-답` 시트, `파트 / 문제 / 답` 열을 사용합니다. 현재 승인된 기준은 **665문항·16단원**입니다. 빈 답, 잘못된 번호, 같은 파트의 중복 번호, 665개와 다른 개수이면 실패하며 생성 파일을 쓰지 않습니다. Excel 원본과 질문은 교정하지 않습니다. JSON의 답은 아래 규칙에 따라 나라와 군주를 분리합니다. 단원·소제목·번호의 SHA-256으로 ID를 만들므로 행 순서를 바꿔도 진도가 유지됩니다. 문항 수를 바꾸려면 원본 변경을 검토한 뒤 승인 기준을 명시적으로 변경해야 합니다.

`data/questions.json`과 `public/questions.json`은 동일하며 `chapters.json`은 단원 목록입니다. 처음에는 단원 목록만 읽고, 문제는 학습·플래시카드·내보내기에 필요할 때 읽습니다. 저장된 기본 문제집 진도가 있으면 단원별 외운 수를 계산하기 위해 문제를 읽습니다.

### 군주 표시와 별칭 관리

각 문항은 `dataVersion: 2`, `answerParts`, `aliases`를 갖습니다. `answer`는 나라 접두사를 제외한 답이며, `answerParts`는 일반 텍스트와 군주 이름·나라를 구분합니다. 표시용 문자열은 JSON에 별도 필드로 저장하지 않습니다. 예를 들어 `백제/의자왕`은 순수 답 `의자왕`과 `{kind:"ruler", name:"의자왕", country:"백제"}`로 나뉩니다. 화면과 PDF는 `renderAnswer(question, {showCountry})`로 표시합니다. Excel/JSON 내보내기는 표시 설정과 무관하게 순수 답과 구조를 보존합니다.

홈의 **왕 이름 앞에 나라 표시**는 기본으로 켜져 있습니다. 보기·정답 공개·플래시카드·오답 목록에 모두 적용되며, 꺼도 채점 기준은 바뀌지 않습니다. `의자왕`, `백제의자왕`을 모두 인정하지만 `대동법/광해군`의 답에 `광해군`만 쓰면 오답입니다. 순서 답의 순서 비교와 수동 정답 인정은 유지합니다.

`고려(성종)`처럼 원래 나라가 적힌 괄호 답은 그 나라를 단원보다 우선합니다. 조선 단원에 있어도 고려 성종으로 구분하고, 표시 설정과 무관하게 원문 `고려(성종)`을 유지합니다. `고려(성종)`, `고려/성종`, `성종/고려`, `고려 성종`, `성종 고려`를 모두 인정하지만 `조선/성종`은 인정하지 않습니다. 기존 괄호 별칭 규칙도 유지합니다. 이 규칙이 순서 맞추기 답의 순서를 바꾸지는 않습니다.

- `data/rulers.json`: `{name, country, aliases}` 배열입니다. 군주만 추가하고 건물·책·불교 종파·대통령은 넣지 않습니다. `문성왕` 속 `성왕`처럼 한글 단어 일부를 인식하지 않습니다. 동명이인은 나라별 항목으로 나누며 나라가 불확실하면 이름만 표시합니다.
- `data/alias-overrides.json`: 문항 ID를 키로 한 문자열 배열입니다. 예: `{"문항의 실제 id": ["광개토대왕"]}`. **원래 답과 같은 의미인 표기**만 넣으세요. 복합 답의 일부만 인정하는 별칭을 추가하지 마세요. 괄호 별칭·나라 접두사·복수 답의 공백/구분자 변형은 자동 생성합니다.
- LLM은 별칭 **후보**를 보강하는 용도입니다. 기존 GPT-6 Luna로 받은 제안도 문제 문맥과 근거를 확인한 뒤 수동 파일에 반영합니다. 가져오기·빌드·학습 중 별칭을 만들기 위한 자동 유료 호출은 없습니다.
- 이번에 검토한 LLM 후보와 적용 범위는 [별칭 검토 기록](../reports/alias-review.md)에 남겼습니다.
- 사전/별칭/Excel을 수정한 다음 `pnpm run import`를 실행하고 저장소 루트의 [reports/import-report.md](../reports/import-report.md)에서 문항 수, 빈 답, 군주 수, 나라별 분포, 모호한 나라, 미확인 군주 후보를 확인합니다. 예상 개수에 맞추기 위해 사전에 없는 단어를 억지로 군주로 분류하지 마세요.
- 이후 `pnpm test`, `pnpm run typecheck`, `pnpm run lint`, `pnpm run build`, `pnpm run test:e2e`를 실행합니다. 모호한 항목과 실제 변환 샘플을 검토한 후 배포합니다.

저장 키는 계속 `hnk_v1`입니다. 이전 저장 형식(version 1)의 ID와 level은 그대로 읽고, 새로 저장할 때 version 2 및 계정별 `dataVersion: 2`로 기록합니다. `showCountry`가 없거나 boolean이 아니면 켜짐으로 읽습니다. 이미 열어 둔 구버전 탭은 새 형식에 저장하지 못하도록 하여 새 설정을 지우는 일을 막습니다. 안내가 나오면 새로고침하세요. 저장된 개인 문제집도 읽을 때 구조를 보강하지만 질문 ID·학습 진도는 변경하지 않습니다.

## 다른 자료 가져오기

- **XLSX/XLS·CSV:** 기기에서 읽고 시트·제목 행·문제/답/단원/소제목/번호 열을 연결합니다. 수식은 실행하지 않습니다.
- **JSON:** 문제 배열 또는 `{questions:[...]}` 형태를 가져옵니다. Excel/JSON 내보내기 파일도 다시 읽을 수 있습니다.
- **PDF·TXT·MD:** 먼저 기기에서 텍스트를 추출합니다. PDF는 필요한 쪽을 고르고, 읽지 못한 쪽과 이미지·도표의 한계를 표시합니다.
- **AI 문제 만들기:** 검토 화면의 텍스트를 직접 확인·수정하고 외부 전송에 동의한 뒤 실행합니다. 기존 NOVA의 **GPT-6 Luna**를 사용합니다. 결과와 근거를 검토·수정하고 별도로 저장해야 학습 문제집이 됩니다.

PDF는 최대 64 MiB, 그 외 파일은 20 MiB, 가져올 문제는 최대 2,000개입니다. PDF는 한 번에 40쪽, 로컬 추출 텍스트는 12만 자까지입니다. AI 전송은 **24,000자·1–30문항**으로 제한하며 긴 내용을 조용히 잘라 보내지 않습니다. 이미지 PDF의 OCR, HWP/DOCX/PPTX 직접 읽기는 이번 버전에 포함하지 않았습니다. 지원하지 않는 파일은 텍스트나 PDF/문제·답 Excel로 내보내 가져옵니다.

개인 문제집은 현재 브라우저에만 남습니다. 원본 파일은 서버에 업로드하지 않습니다. AI 생성 요청 때만 확인한 텍스트를 서버와 외부 제공업체로 보냅니다. 자동 외부 호출은 없습니다. 모델은 내용을 틀리게 해석할 수 있으므로 정답과 원문을 대조하세요. 형식·근거 검사에서 일부 문제가 발견되어도 사용할 수 있는 초안은 짧은 경고와 함께 제공합니다.

문제집의 **내보내기**에서 Excel, JSON, 한글 문제·정답 PDF를 만듭니다. PDF는 문제 뒤에 정답을 따로 배치하며, 원본 교재의 지면을 그대로 복제하는 기능은 아닙니다. PDF용 큰 글꼴과 파일 파서는 사용할 때만 불러옵니다.

## 학습과 저장

- 아직 외우지 못한 문제를 7개씩 선택합니다. 답 고르기 → 직접 쓰기 → 외운 문제로 진행합니다. 틀리면 해당 라운드 뒤에 다시 넣습니다.
- 정답은 0.85초 후 진행하며 Enter로 넘길 수 있습니다. 오답은 정답을 보여주고 계속하기를 기다립니다. 직접 쓰기의 수동 정답 처리도 제공합니다.
- 한글 조합 중 Enter를 제출로 처리하지 않습니다. 보기 1–4, Enter, 카드 Space·좌우 방향키를 지원합니다.
- 플래시카드의 알아요/몰라요는 학습하기 진도를 변경하지 않습니다.
- `hnk_v1` 키 하나 안에서 계정 범위별 문제집·진도·선택·테마를 구분합니다. 토큰과 API 주소를 저장하지 않습니다. 저장 오류를 알리고 메모리에서 학습을 계속합니다. 손상된 원본 저장값을 조용히 덮어쓰지 않습니다.
- 같은 계정의 다른 창에서 기록이 바뀌면 오래된 화면의 저장을 거절하고 안내합니다. 브라우저 Web Locks로 저장을 직렬화하며, 이 기능을 지원하지 않는 브라우저에서는 메모리 학습·문제집 내보내기는 가능하지만 새 기록을 저장하지 않습니다.
- 가져오기 화면의 작성 중 초안과 AI 요청 식별자는 학습 홈으로 이동해도 유지됩니다. 로그아웃·새로고침하면 저장하지 않은 초안은 사라지므로 문제집으로 저장하거나 내보낸 뒤 닫으세요.
- **기록 지우기**는 두 단계 확인 후 현재 문제집 진도만 초기화합니다. 문제집·다른 문제집의 기록·다른 계정의 기록은 유지합니다.
- 로그아웃하면 화면과 진행 중 연결을 비우지만 브라우저의 학습 기록은 남습니다. 다른 기기와 동기화하지 않습니다. 이 저장 방식은 기기 자체의 다른 이용자가 개발자 도구로 접근하는 것을 막는 암호화 보관이 아닙니다.

문제집이 너무 작아 서로 다른 보기 네 개를 만들 수 없으면 가능한 보기만 제공합니다. 두 항목 순서는 가능한 순열이 두 개입니다. 정답 하나뿐인 문제집은 직접 쓰기로 시작합니다. 그럴듯한 가짜 사실을 추가하여 네 칸을 채우지 않습니다.

## AI 서버 운영

새 환경변수·패키지·데이터베이스 이전은 필요 없습니다. 기존 `Settings`의 NOVA 연결과 GPT-6 Luna 모델을 재사용합니다.

- 인증된 `GET /study/capabilities`, `POST /study/generate`만 제공합니다.
- 사용자별 6회/시간, 전체 30회/시간. 시간표 인식과 동시 처리 슬롯 2개를 공유합니다.
- 같은 요청 UUID는 같은 입력·계정에서만 재확인합니다. 실패해도 자동으로 새 유료 요청을 만들지 않습니다. 새 요청은 추가 비용 안내와 재동의를 거칩니다.
- 서버가 다시 시작되면 이전 `generation_epoch` 요청을 거절합니다. 동일 UUID의 결과/실패 기록은 메모리에 최대 512개 유지하며, 포화 시 신규 요청을 거절합니다. 기존 결과 확인은 유지됩니다. 기록은 서버 재시작 시 사라지며 DB·파일에 보관하지 않습니다.
- 현재 서비스는 API 단일 프로세스 기준입니다. 다중 API worker로 늘리기 전에 요청 기록·요청 제한을 공유 저장소로 옮겨야 합니다.

## 검사

```powershell
pnpm test
pnpm run typecheck
pnpm run lint
pnpm run format:check
pnpm run build
pnpm run test:e2e
```

Windows E2E는 기본으로 설치된 Microsoft Edge를 사용합니다. `STUDY_BROWSER_EXECUTABLE`로 별도 시험 브라우저의 실행 파일을 지정할 수 있습니다. Linux CI에서는 `pnpm exec playwright install --with-deps chromium` 후 실행합니다. `pnpm run serve` 실행 중 `node scripts/audit.mjs`로 모바일 Lighthouse와 초기 전송 크기를 검사합니다.

Pages 배포 후에는 `node scripts/check-public-assets.mjs`로 실제 공개된 자산의 학습 흐름을 검사합니다. 브라우저 안에서만 가상 부모·계정 범위를 제공하며 운영 계정·DB·유료 API를 사용하지 않습니다. 실제 운영 인증의 종단 검사를 대신하는 것은 아닙니다.

기존 서비스 회귀는 저장소 루트의 `node --test tests/*.test.mjs`, `python -B -m unittest discover -s tests -q`를 사용합니다. 운영 자료 대신 합성 데이터로 검사합니다. 통합 브라우저 검사는 `tests/study-parent-fixture.py`와 `tests/study-parent-browser-smoke.cjs`에 있습니다.

## 배포

기존 `.github/workflows/pages.yml`이 main 변경 시 pnpm 설치·검사·정적 빌드를 수행하고, `study/out`을 공개 산출물의 `study/` 아래에 넣습니다. 기존 서버 연결 설정 게시·만료 갱신을 유지합니다. 개발 폴더·seed·서버 소스·비밀값은 Pages 산출물에 넣지 않습니다.

PR에서는 `study-checks.yml`이 검사와 E2E를 실행하고 정적 미리보기 파일을 Actions 아티팩트로 제공합니다. **Vercel 프리뷰 URL은 생성하지 않습니다.** 이는 기존 주소·배포를 유지하기로 한 사용자 선택에 따른 변경입니다.

학습·파일 읽기는 정적 웹 배포로 반영됩니다. 새 AI 생성 API는 검증된 서버 소스 반영과 API 재시작이 필요합니다. 배포 전 현재 전사·업로드·AI 작업을 확인하며 Qwen과 터널을 불필요하게 재시작하지 않습니다.

실제 로컬·프로덕션 검사 결과와 한계는 [검증 기록](../docs/STUDY_VALIDATION.md)에 기록합니다.
