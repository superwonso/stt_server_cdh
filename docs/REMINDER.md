# 리마인더

## 통합 구조

GitHub Pages의 기존 `index.html`·`app.js`가 로그인 이후 **여백 / 리마인더** 탭을 제공합니다. 별도 사이트, 계정, iframe은 없습니다. `web/reminder.js`·`reminder.css`는 독립 화면 모듈이고 `web/review-schedule.js`는 순수 날짜 계산입니다. 여백 탭을 가려도 마이크와 원본 음성·전사 전송 대기열은 유지됩니다. 로그인 만료·계정 또는 서버 변경 시 리마인더의 요청과 개인 화면을 초기화합니다. 새로고침하면 여백 탭으로 시작합니다.

현재 저장소의 기본 ES 모듈 화면, `server/app.py`의 FastAPI 인증 의존성, `server/db.py`의 SQLite 연결과 기존 schema23을 기준으로 통합했습니다. `/review` API는 동일한 서버와 Bearer 로그인·운영 접근 제어를 사용합니다. 상단 탭은 로그인 전에는 숨깁니다.

## 저장과 API

schema24는 기존 테이블과 행을 보존하고 리마인더 테이블만 추가합니다. 사용자 식별자는 기존 `users.username`이며 모든 개인 테이블은 계정 삭제 시 CASCADE입니다.

- `review_profiles`: 사용자별 설정, 시간표, 전체 revision.
- `review_items`, `review_routines`, `review_exams`: 복습·루틴·시험 문서. 시험은 사용자/과목/종류 유일.
- `review_sources`: 삭제된 자동 수업도 다시 생성하지 않게 출처 키 보존.
- `review_requests`: 요청 ID 중복 방지 영수증.
- `review_undo`: 사용자별 8초 되돌리기 상태. 다른 기기 수정 뒤에는 거절.
- `review_parse_usage`, `review_parse_leases`: 한국 날짜별 유료 인식 한도와 동시 요청 제한.
- `review_holidays`: 공개 연간 공휴일 데이터. 개인 데이터가 아닌 이 테이블만 공용입니다.

API:

- `GET /review/state`: 내 전체 상태와 KST 오늘. 시간표의 아직 생성하지 않은 수업을 트랜잭션으로 생성합니다.
- `POST /review/actions`: `{request_id, revision, action, payload}`. 복습/이동/날짜 수정/설정/시간표/따라잡기/루틴/시험/되돌리기를 처리하고 갱신한 상태를 반환합니다. 오래된 revision은 409이며 화면 새로고침 후 다시 선택해야 합니다. 응답 유실은 같은 요청 ID로 확인해 중복 저장을 막습니다.
- `POST /review/timetable/parse`: JSON `{text}` 또는 원본 PNG/JPEG/WebP 요청 본문. 인식한 `{classes}`만 반환하며 시간표를 자동 저장하지 않습니다.

## 실행과 설정

별도 Node 빌드나 데이터 서버는 필요 없습니다. 기존 Python 설치와 API 시작 명령을 사용합니다. 최신 의존성 설치 시 기존 Qwen 경로에서 사용되던 Pillow를 명시적으로 고정합니다. 최초 새 API 시작의 `Database.initialize()`에서 schema24와 공휴일 데이터가 적용됩니다. 운영 반영은 일관된 DB 백업과 처리 중인 작업 확인 뒤 진행합니다.

시간표 인식은 기존 **NOVA의 `MINDLOGIC_API_KEY`, `MINDLOGIC_BASE_URL`, `MINDLOGIC_MODEL`**을 사용합니다. 모델 기본값은 `gpt-6-luna`입니다. 새 공급자나 별도 키를 브라우저에 넣지 않습니다. `REVIEW_TIMETABLE_RECOGNITION_ENABLED=0`이면 인식 기능을 끕니다. 키가 없는 환경에서도 직접 입력은 정상 동작합니다.

인식은 사용자가 버튼을 누를 때만 호출하며 1회 요청, 사용자당 KST 하루20회, 사용자 동시1회/서버 동시2회, 전체75초 제한입니다. 실패한 공급자 호출도 호출 한도에 포함합니다. 최대10MiB 이미지·2천만 픽셀·정지 이미지1장 또는6천자 글을 받습니다. 이미지는 메모리에서만 처리하고 원본이나 공급자 응답을 로그/DB/파일에 남기지 않습니다. 과목·시간이 잘못 읽힐 수 있으므로 편집 화면에서 반드시 확인합니다.

공식 공급자 계약: [NOVA Chat Completions](https://docs.mindlogic.ai/docs/general/api-gateway/reference/chat-completions). 유료 호출이나 운영 인증정보 없이 실행 가능한 합성 HTTP 응답 테스트를 제공합니다.

## 공휴일 갱신

초기 `data/review-holidays/2026.json`은 사용자가 제공한2026년 목록입니다. 해가 바뀌기 전에 같은 형식으로 공식 발표 자료를 확인해 파일을 준비하세요. 근로자의 날은 학교 공휴일로 넣지 않습니다.

```powershell
.\.venv-win\Scripts\python.exe scripts/update-review-holidays.py --year 2027 --input "C:\path\holidays-2027.json"
```

형식: `{"year":2027,"source":"검증한 출처","holidays":[{"date":"2027-01-01","name":"신정"}]}`. 스크립트는 잘못된 날짜·중복·이름·크기를 거절합니다. 검토한 변경 파일을 배포하고 API를 다시 시작하면 해당 연도만 대체하며 다른 연도는 보존합니다. 공공데이터포털 키나 네트워크 동기화는 요구하지 않습니다. KASI 자동 동기화는 선택 확장으로 남깁니다.

## 프로토타입과 차이

- 브라우저 로컬 저장소·Claude 아티팩트 연결을 사용자별 서버 저장으로 대체했습니다. 기존 프로토타입의 실제 데이터는 자동으로 읽거나 옮기지 않습니다.
- 브라우저 시간대에 관계없이 한국 날짜를 사용합니다. 서버가 최종 상태와 권한을 검증합니다.
- 여백의 색·서체·로그인·상단 바를 공유합니다. 리마인더 본문은 휴대폰과 다크 모드에 대응합니다.
- 빈 화면에 예시 기록을 생성하지 않습니다. 사용법과 입력 폼만 제공합니다.
- 시간표 따라잡기는 서버 트랜잭션으로 모두 저장하거나0개 저장합니다. 실패 뒤 다시 실행해도 기존 키가 중복되지 않습니다.
- 동시 수정이 있으면 안전하게 새 상태를 불러온 뒤 다시 선택합니다. 다른 기기의 수정을 되돌리기로 지우지 않습니다.
- 브라우저 알림, 오전8시 이메일, 프로토타입 JSON 가져오기는 선택 과제이며 기본 구현에 포함하지 않습니다. 향후 가져오기는 소유권/출처 키/시험 체크 키를 검증한 미리보기와 단일 트랜잭션으로 설계해야 합니다. 알림은 사용자 옵트인과 발송처 설정이 먼저 필요합니다.

검증 기록과 실제 배포 범위는 완료 보고에 별도로 기재합니다.

## Windows 운영 반영 · 2026-09-29

사용자 배포 승인 후 진행 중인 전사·정리·파일 처리와 최근 음성 갱신이 없는 것을 확인하고 API만 재시작했습니다. 일관된 비공개 DB 백업 후 schema24를 적용했으며 모든 기존 테이블의 기존 열 값이 백업과 일치하고 DB 무결성 검사를 통과했습니다. 새 개인 리마인더 테이블은 빈 상태이고 공개 공휴일만 초기화했습니다. 기존 운영 설정·Qwen 모델 프로세스·터널 프로세스·공개 API 주소를 유지했으며 API와 터널 준비 상태를 확인했습니다. GitHub Pages는 같은 저장소의 기존 배포 워크플로로 게시하며 게시된 정적 파일과 해당 커밋의 일치 여부를 별도 확인합니다.

## 예제 배치와 여백의 과목 선택 · 2026-09-29

화면은 예제처럼 최대1180px의 독립된 두 열을 사용합니다. 왼쪽은 오늘의 복습·새로 공부한 내용·앞으로7일, 오른쪽은 달력·기억 곡선이며 오늘 목록의 길이에 따라 곡선이 밀리지 않습니다. 아래에는 루틴·시험·시간표·전체 기록·복습 간격이 전체 폭으로 이어집니다. 920px 이하에서는 오늘→달력→새 내용→7일→곡선 순서입니다. 색은 여백의 기존 색을 유지합니다.

시간표의 과목명은 여백의 새 수업 이름(파일 가져오기 포함), 이름·과목 정리의 과목 분류, 강의별 자료·복습의 강의 만들기에서 고를 수 있습니다. 반복 요일의 같은 과목은 하나의 선택지로 표시하고 직접 입력도 유지합니다. 선택은 입력값만 채우며 수업 이름이나 과목 저장, 강의 생성은 기존 버튼으로 확정합니다. 시간표를 수정한 뒤 여백으로 돌아오거나 목록 새로고침을 누르면 갱신됩니다.

`GET /review/timetable`은 현재 사용자 시간표의 classes/from/until만 읽으며 profile·복습 항목·revision·되돌리기를 생성하거나 변경하지 않습니다. 기존 DBschema24를 유지하고 의존성·모델·유료 인식 계약은 변경하지 않습니다. 후보는 메모리에만 두며 계정·토큰·서버 변경과 로그아웃 시 취소·초기화합니다. 불러오기 실패 시 직접 입력을 유지합니다.

과목 분류 문자열과 강의 묶음 ID는 현재 서로 다른 기능입니다. 이름이 같다고 기존 강의에 자동 연결하거나 같은 학기로 추측하지 않습니다. 강의별 자료를 묶으려면 강의 만들기/현재 수업의 강의 연결에서 직접 선택합니다.

검증: 전체 JavaScript793 통과, Python1372 실행(1284 통과·88 환경별 제외, 실패0). 합성 시간표로 실제 로그인·새 수업 이름 선택·과목 분류 저장/다시 열기·강의명 선택/명시 생성·로그아웃과 기존 복습 흐름을 확인했습니다. 1280/1024/920/390/320px 및 다크 모드에서 넘침과 앱JS오류가 없었습니다. 실제 운영 개인 자료나 유료 호출은 사용하지 않았습니다.

다음 연동 후보는 복습 카드에서 사용자가 연결한 수업 열기, 북마크·필기를 출처 링크가 있는 복습 항목으로 추가하기, 실제 수업일과 시험 범위를 확인하여 강의 복습 정리본 만들기입니다. 이번에는 구현하지 않았으며 단순 열람을 복습 완료로 취급하거나 원래 수업을 중복 등록하지 않는 별도 연결 설계가 필요합니다.
