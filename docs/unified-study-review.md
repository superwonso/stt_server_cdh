# 통합 수업 정리·자료·복습 구현 계약

요청 원본 범위: 후보정/요약/영어 번역/정리본을 하나로 통합, 수업 내용 보존, PDF/PPTX→Markdown 보조자료, 강의명과 수업 일시 분리, 동일·관련 강의 묶음 조회 및 누적 복습.

## 구현 기준

- 새 화면에는 하나의 수업 정리본 생성 흐름. 이전 결과는 별도 기록으로 읽고 내려받을 수 있으며 자동 재생성하지 않는다.
- 개요는 요청당 한 개부터 네 개의 짧은 한국어 항목으로 요청한다. 개요가 없거나 형식이 잘못되어도 받은 상세 설명과 원문은 보존하며 하단에 짧은 경고를 표시한다. 핵심 흐름은 상세 본문을 대체하지 않는다. 모든 원문 구간은 서버 스냅샷에서 순서/내용/시각 그대로 한 번씩 정리본에 포함한다. AI의 의미 보존을 ID 일치만으로 보장했다고 표시하지 않는다.
- 일부/잘린/부정확한 형식 응답도 사용 가능한 본문을 제공하고, 미확인 구간은 원문과 함께 표시하며 문제를 하단에 요약한다. 통신 중단/취소/저장 실패 및 권한 검사는 유지한다.
- PDF/PPTX 자료를 업로드하고 Markdown을 확인/다운로드/삭제할 수 있다. 페이지/슬라이드 출처를 보존하고 이미지·스캔 등 미추출 영역을 명시한다. 지원되지 않는 자료는 완전 변환 성공으로 표시하지 않는다.
- 변환은 Windows/Linux에서 제한된 별도 프로세스로 수행한다. 자료는 비공개 저장 및 소유권 검사, 형식·크기·압축해제·시간·메모리 제한을 적용하고 외부 링크를 가져오거나 매크로/스크립트를 실행하지 않는다.
- 자료는 사용자가 정리본 생성을 요청할 때만 기존 NOVA로 보내는 보조 근거이며, 원문을 대체하거나 문서 속 명령을 따르지 않는다. 결과에 출처와 자료 상태를 표시한다.
- 강의 그룹, 수업 회차 제목, 실제 일시를 분리한다. 기존 제목/생성시각/자료를 추측해 덮어쓰지 않고 사용자가 연결·수정한다. 모든 그룹과 자료는 사용자별로 격리한다.
- 강의별로 누적 수업/자료를 한곳에서 조회하고 명시 요청으로 통합 복습 정리본을 생성/저장/다운로드한다. 선택 범위와 전체 원문을 보존하고, 생성 중 소스 변경/계정 변경/휴지통/재시작/중복 요청을 검사한다.
- 기존 마이크/파일 전사, 마지막 음성 저장, 보류 복구, 계정·권한·WAV, Qwen/ROCm/Windows 프로세스 경로의 회귀를 확인한다.
- 합성 PDF/PPTX/수업으로 API·DB·UI 통합 검증, 전체 해당 Python/JavaScript 회귀, 실제 브라우저 모바일/데스크톱 확인을 수행한다. 추가 유료 검증은 범위를 정해 별도 승인 뒤 실행한다.

## 개발 위치와 운영 분리

`feature/unified-study-review`의 독립 worktree에서 개발·검증했으며, 그동안 운영 소스 checkout·DB·Drive·프로세스와 분리했다. 검증을 마친 뒤 2026-09-26 Windows 운영 API에 적용했다. 아래 운영 적용 결과와 GitHub/Pages의 공개 릴리스 절차는 별도로 구분한다.

## 변환 방식

사용자가 제안한 [convert-pdf-to-md 스킬](https://github.com/github/awesome-copilot/blob/main/skills/convert-pdf-to-md/SKILL.md)을 검토했다. 스킬의 MarkItDown 텍스트 추출 방식과 이미지 미지원 고지를 참고하되, 업로드 서버에는 페이지/슬라이드 출처와 자원 제한을 지원하는 별도 변환기를 사용한다. 스킬의 폴더 삭제·일반 예외 출력 코드는 서버에 복사하지 않는다. 변환기와 제한·검증은 [MATERIAL_CONVERSION.md](../MATERIAL_CONVERSION.md)에 기록한다.

## 사용 흐름

1. 수업을 마치고 저장한 뒤 **수업 정리본**을 연다. 후보정, 한국어 번역, 개요, 상세 정리, 각 위치의 원문을 하나의 결과에서 읽고 Markdown으로 내려받는다.
2. **PDF · PPTX 강의자료**에서 파일을 선택한 후 업로드한다. 전송 완료 후 **Markdown으로 변환**을 눌러 추출 내용을 확인한다. 업로드/변환만으로 유료 AI 요청은 발생하지 않는다.
3. **강의별 자료 · 복습**에서 강의를 만들고 현재 수업을 연결한다. 회차 제목과 실제 수업 일시를 별도로 저장한다. 기존 생성 시각을 실제 수업 일시로 추정하여 저장하지 않는다.
4. 강의 공통 자료는 그 강의의 모든 회차에 보조 자료로 쓰인다. 개별 수업 자료는 해당 회차에 연결된다. **전체 수업** 또는 체크한 회차로 복습을 명시적으로 요청한다. 전체 원문을 수업별로 보존하며, 분량에 따라 여러 유료 모델 요청이 발생할 수 있다.
5. 자료/원문/강의 범위가 바뀌면 기존 결과를 갱신 필요로 표시한다. 생성 중 소스가 바뀌면 이전 스냅샷의 결과를 최신으로 저장하지 않는다. 같은 모델·범위·소스의 완료 결과는 새 요청 ID에서도 재사용하여 응답 유실 뒤 중복 호출을 방지한다.
6. 기존 후보정·요약·번역 결과는 접힌 **이전 AI 결과**에서 조회·다운로드한다. 신규 화면의 생성은 통합 정리본 하나로 제공한다. 이전 클라이언트 호환 API는 유지한다.

## 보존과 한계

- `coverage.complete`는 서버가 **원문 텍스트·ID·시각·순서를 전부 보존했음**을 뜻한다. AI 설명의 의미상 완전성을 보장하지 않는다. 화면과 Markdown에 이 차이를 표시한다.
- 원문은 상세 구간마다 접어서 볼 수 있다. 생략/빈 응답/잘린 응답에서는 받은 본문과 전체 원문을 제공하고 문제를 하단에 짧게 표시한다.
- 자료의 그림·스캔·복잡한 수식/도표는 텍스트 추출로 완전히 해석할 수 없다. OCR을 자동 호출하지 않는다. 미추출 경고와 원본 다운로드를 제공한다.
- PDF/PPTX 원본은 비공개 `data/study-materials`에 저장되고 변환문과 AI 결과는 DB에 저장된다. Drive 전송이나 SQLite 실시간 동기화는 추가하지 않는다.
- 기존 암호화 복구 백업은 DB와 고정 설정만 담는다. **자료 원본 파일은 포함하지 않는다.** 새 manifest의 `material_files_omitted` 수치로 이를 고지하고 구형 manifest 검증도 유지한다. 복원/이동 시 자료 폴더도 별도로 안전하게 보존해야 원본 재다운로드가 가능하다. DB 속 변환문은 보존된다.
- API를 재시작하면 이미 시작했던 AI/자료 작업을 중단 상태로 마감한다. 유료 호출을 자동 재생하지 않는다. 사용자가 상태를 확인한 뒤 명시적으로 다시 요청할 수 있다.

## 개발 검증과 운영 적용

개발은 별도 worktree와 합성 DB에서 수행했다. 개발 검증용 변환 의존성은 격리된 `work/.venv-materials`에 설치했다. 일부 앱 회귀는 기존 Windows Python 실행 파일과 패키지를 읽기 전용으로 사용하되, 작업 디렉터리와 가져오는 서버 소스는 독립 worktree로 고정했다. 개발 검증 중에는 운영 Python 의존성, DB, 계정, 서비스, Cloudflare 주소를 변경하지 않았다. 검증 후 Windows 운영 적용 결과는 아래에 별도로 기록한다.

운영 적용 시에는 새 자료 의존성 설치, API 배포, DB v23의 추가 테이블/열 생성, 같은 버전의 정적 화면 배포가 필요하다. API와 웹 버전을 함께 검토하고, 작업 중인 수업과 AI 작업을 확인한 뒤 API만 재시작한다. Qwen 모델·revision·분리 프로세스와 기존 Linux/ROCm 경로는 변경하지 않는다. DB 다운그레이드나 복사본의 동시 운영을 수행하지 않는다.


### 검증 결과 (2026-09-25)

다음은 독립 개발 브랜치에서 수행한 검증 기록이다. **Windows 운영 적용은 2026-09-26 완료**했으며, 그 결과는 아래 별도 항목에 기록한다. 개발 검증이나 Windows API 기동 성공만으로 GitHub/Pages의 공개 웹 게시까지 완료됐다고 해석하지 않는다.

#### 승인된 유료 모델 검증: 총 6회

실제 사용자 녹음·수업·첨부자료 대신 합성 한국어/영어 수업과 합성 보조자료만 NOVA의 `gpt-6-luna`로 보냈다. 이 검증 수에 자동 재호출이나 별도의 실제 사용자 요청은 포함하지 않는다.

| 구분 | 실제 호출 | 결과와 확인 범위 |
| --- | ---: | --- |
| 최초 요청 계약 | 4회 | 모두 HTTP 200. 한국어·영어 상세 정리, 정확한 전체 원문 보존, 두 회차 복습을 확인했다. 단일 정리본에서는 개요·자료 인용이 없고 경고도 없어, 요약 기능이 검증됐다고 판정하지 않았다. |
| 개요·인용 요청 수정 후 한국어 | 1회 | 8.609초. 개요 2개, 자료 인용 3개, 원문 6/6개 보존. |
| 개요·인용 요청 수정 후 영어 | 1회 | 13.313초. 한국어 상세 정리, 개요 3개, 자료 인용 3개, 원문 6/6개 보존. |

개요를 선택적으로 쓰던 지시를 필수 요청으로 바꾸고 `overview`와 `paragraphs`를 통합 전용 JSON 계약으로 명시했다. 누락된 개요는 상세 설명을 폐기하는 이유로 쓰지 않고 하단 경고를 남긴다. 수업과 같은 내용을 뒷받침하는 자료도 인용할 수 있도록 했으며, 무관한 자료 인용은 요구하지 않는다.

위 시간은 각 합성 입력의 단일 요청 관측값이다. 긴 수업의 처리 시간·동시 처리 성능·장시간 안정성이나 AI 설명의 의미상 완전성을 보장하지 않는다. 원문 6/6 보존과 개요·인용 개수는 구조 확인이며, 번역·설명의 모든 주장이 정확하다는 평가는 아니다.

#### API·저장·화면 검증

- 합성 DB와 가짜 모델로 소유자 격리, 강의·회차 revision 충돌, 원문/자료 스냅샷 변경, 권한 취소, 취소·종료, 재시작 후 유료 요청 비재생, 저장 실패·커밋 응답 유실 이후 중복 요청 방지, 완료 결과의 갱신 필요 표시를 검증했다. 전체 회귀 실행 수에 집중 테스트를 중복 합산하지 않는다.
- 실제 headless Microsoft Edge의 독립 컨텍스트에서 1280px와 390px를 확인했다. 개요·상세·접힌 원문, 원문 공백과 HTML처럼 보이는 문자 보존, 자료 인용 이동, Markdown 미리보기, 강의·회차와 누적 복습, 접힌 이전 AI 결과를 검증했다.
- 합성 API에서 자료 업로드 1회→변환 1회→기존 정리본 갱신 필요 표시→사용자의 명시적 정리본 생성 1회를 확인했다. 업로드·변환·조회만으로 AI 생성 요청이 발생하지 않았다.
- 브라우저 스크립트 오류 0, 콘솔 오류 0, 가로 넘침 0, 예상 밖 요청 0, 외부 요청 0이다. 스크린샷 8개를 저장하고 육안으로 확인했다. 자료 변환 자체는 이 브라우저 검사에서 합성 응답을 사용했으며, 실제 변환기는 별도의 Python 회귀로 검증했다.
- 최종 전체 Python 회귀: **1,309개 실행, 1,221개 통과, 88개 제외, 실패·오류 0개**, 167.741초. 제외한 88개는 통과로 계산하지 않는다.
- 최종 전체 JavaScript 회귀: **720개 통과, 제외·실패 0개**, 5,445.815ms. 앞서 수행한 집중 검사와 유료·브라우저 검증을 전체 테스트 수에 중복 합산하지 않는다.

로컬 검증 산출물은 작업 공간의 `outputs/unified-study-browser/report.json` 및 같은 폴더의 스크린샷, `outputs/unified-study-paid-validation.json`, `outputs/unified-study-paid-followup.json`에 보관한다. 합성 본문·토큰·키를 이 문서에 넣지 않는다.

#### 미검증 및 적용 전 조건

실제 사용자 녹음·첨부문서, 이미지·스캔의 OCR, 긴 수업의 의미 정확도, 실제 Linux/ROCm 기동, 물리 모바일 기기와 학교 네트워크, 장시간 동시 사용은 이번 검증 범위가 아니다. 기능 회귀 통과가 이를 대신하지 않는다.

운영 사전 확인은 읽기 전용으로 수행했다. 확인 시점에 API·모델·터널이 모두 준비 상태였고, 진행 중 AI·파일 전사·음성 전사 작업과 최근 120초 음성 갱신은 모두 0이었다. 이 사전 확인 뒤 아래 운영 적용을 진행했다.

### Windows 운영 적용 결과 (2026-09-26)

- 운영 사전 백업을 확인하고 자료 변환에 필요한 의존성을 설치했다. 패키지 의존성 검사(`pip check`)가 통과했다.
- DB v23의 추가 마이그레이션을 적용했다. 적용 전 스냅샷과 비교하여 **모든 기존 테이블의 기존 열 값이 그대로 보존됨**을 확인했다. 기존 계정·권한·수업·원문·결과를 새 값으로 대체하지 않았다.
- 새 코드로 API를 기동하여 준비 상태를 확인했다. 기존 Qwen 모델 프로세스와 터널 프로세스를 유지했으며, 공개 API 주소와 운영 설정도 그대로 보존했다.
- 운영 적용 검증 보고서의 `applied`와 `passed`는 모두 참이다. 비공개 경로·프로세스 ID·계정·설정 값은 공개 문서에 기록하지 않는다.

운영 적용 보고서는 작업 공간의 `outputs/unified-service-activation.json`에 보관한다. 이 기록은 Windows API/DB 적용 결과이며 GitHub/Pages 게시 성공 증빙은 아니다.

### 공개 릴리스 확인 절차

GitHub에 공개 소스를 반영할 때는 비공개 설정·자료가 제외됐는지 확인하고 저장소 검사와 Pages 배포 결과를 확인한다. 게시 후에는 공개 정적 자산이 같은 릴리스의 API 계약을 사용하는지, 공개 주소와 인증 경계가 유지되는지 확인한다. 커밋·배포 실행·게시된 자산 검증은 실제 완료 결과로 별도 기록한다. Qwen·터널의 재시작이나 공개 API 주소 변경은 이 웹 릴리스의 필수 단계가 아니다.
