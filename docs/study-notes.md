# 수업 정리본

현재 배포 상태와 최신 검증 결과는 [HANDOFF](../HANDOFF.md)를 따릅니다.

## 기존 기능과의 구분

후보정과 한국어 번역은 원문 구간별 대조를 유지합니다. 수업 정리본은 별도로 저장하는 복습용 AI 초안으로, 시간대별 문단·짧은 주제·핵심 표현 강조·용어 복원 목록을 제공합니다. 확정된 수업의 받아쓴 원문만 사용하고, 필기·직접 수정본·다른 수업·이전 AI 결과는 입력으로 사용하지 않습니다.

전체 수업 문맥을 참고해 영어 문장·표현을 한국어로 풀어 번역하고, 영어를 한글 음차로 받아쓴 부분도 의미를 복원해 한국어로 설명하도록 지시합니다. 필요한 원어만 괄호 안에 보조 표기할 수 있습니다. 영어를 그대로 나열하거나 내용만 짧게 추린 단순 요약을 목표로 하지 않습니다. 상위 편집 지침에는 다음 요청을 그대로 포함합니다.

> 전체적인 맥락을 고려해서 영어로 작성되어 있는 것들을 한글로 번역해줘. 영어인데 한글로 써져있는 것들도 있으니 이것도 해결해주면 좋을거같아

추정한 용어는 확인 필요로 표시하고, 복원 근거가 부족한 표현은 원문과 함께 불명확 표시를 남기도록 지시합니다. 이름·논리·조건·숫자를 그럴듯하다는 이유만으로 수정하라는 지시는 하지 않습니다. 비공개 예시 문서에서는 형식적 특징만 참고했으며 문서 본문·개인 이름·전공별 용어를 소스나 프롬프트에 복제하지 않았습니다.

## 입력과 출력

1. 서버가 확정 원문과 revision을 고정합니다. 후보정·번역·수동수정을 적용하지 않은 전체 원문 구간을 `S000001` 같은 요청용 표식으로 바꿔 하나의 `source_markdown` 문서를 구성합니다. 모델에는 이 Markdown 파일의 **내용**이 입력임을 명시합니다. 새 파일 업로드 기능이 아니며, 원문 파일을 따로 업로드할 필요도 없습니다.
2. 기존 NOVA 키와 `TRANSLATION_MODEL`을 사용합니다. 새 키나 모델 교체는 필요하지 않습니다. 문서 내용을 요청 본문에 넣으며 별도 파일 저장 API로 업로드하지 않습니다.
3. 출력이 길면 대상 구간만 나누되 **모든 요청에 같은 전체 원문 Markdown**을 넣습니다. 잘린 결과를 이어 붙이는 무제한 재요청은 하지 않습니다.
4. 모델은 Markdown 본문과 원문 대응 표식을 검증용 JSON으로 반환합니다. 서버가 형식·출처·순서를 검사하고 시간 범위를 직접 계산해 최종 Markdown 하나로 제공합니다. 따라서 문장별 원본 대조를 포기한 무검증 자유 형식 출력은 아닙니다.

출처 ID는 모든 원문 구간을 순서대로 정확히 한 번씩 포함해야 하고, 문단은 인접 구간만 묶습니다. **숫자·연락처의 추가·변경·생략·순서 차이나 원문에 없는 용어 복원만을 이유로 결과 전체를 버리지 않습니다.** 용어 복원 목록도 원문·본문과 글자가 정확히 일치할 필요는 없으며, 사실이 확인된 정정 내역이 아니라 AI의 제안으로 읽어야 합니다. 기존 후보정·문장별 번역의 검증 기준을 함께 완화하는 변경은 아닙니다.

모델에 보내기 전 모든 숫자와 형식을 인식한 일부 연락처를 가리는 처리는 유지합니다. 반환된 제목·본문·용어 목록의 알려진 가림 표식은 서버에서 원래 값으로 복원합니다. 표식 순서·개수가 달라도 저장하고, 원래 값이 없는 표식은 값을 지어내지 않고 `[가려진 값 확인 필요]`로 표시합니다. 이름 등 모든 개인정보를 찾는 완전한 익명화는 아닙니다.

제목·계정 ID·원문 구간 UUID·시각·음성은 모델 입력에 넣지 않습니다. 수업 내용에 포함된 이름 등은 남을 수 있으므로 민감한 수업에는 생성 버튼을 누르지 마세요. 외부 HTML·이미지·링크는 실행하지 않으며 본문의 굵은 강조만 제한적으로 표시합니다.

## 처리 한도와 실패

- 입력 상한: 원문 250,000자·50,000구간·구간당 24,000자. 가림 뒤 실제 요청 크기와 출력 계획의 별도 상한이 있어 이보다 짧아도 거절할 수 있습니다.
- 최대 32회 모델 요청. 한 번의 출력 대상은 최대 64구간·예상 JSON 약 12 KiB이고 응답 토큰 상한은 16,384입니다. 요청 가능한지 비용 발생 전에 점검합니다.
- 따라서 실제로 처리 가능한 구간은 최대 2,048개이며 길이에 따라 더 줄어듭니다. 최종 검증 문서는 1 MiB, Markdown 파일은 4,000,000바이트까지 허용합니다.
- 한 계정당 진행 중인 정리본 하나, 새 생성 최대 시간당 6회. 완료 결과와 진행 상태 조회는 재생성이 아닙니다.
- 중단·응답 유실·저장 실패 시 시작한 작업을 자동으로 다시 호출하지 않습니다. 서버가 재시작되면 미시도 대기 작업만 재개하고 이미 시작한 작업은 중단으로 표시합니다.
- 출력 길이 중단, 모델 거절, 형식·원문 구간 불일치는 계속 실패로 안내합니다. 일부만 성공한 결과는 완료본으로 저장하지 않습니다. 숫자·연락처·복원 용어 차이는 저장 실패 사유가 아닙니다. 상태 새로고침 후 다시 만들기를 누르는 것은 새 요청입니다.
- 이전 검증 기준으로 이미 실패한 작업에는 결과 문서가 남아 있지 않습니다. 변경 배포 후 **다시 만들기**를 눌러야 새 기준으로 생성·저장하며, 기존 실패 작업을 자동 재호출하지 않습니다.

요청 시점과 저장·조회 시점에 소유자·원문 revision·수업 종료·휴지통 상태를 검사합니다. 관리자에게는 사용자별 보관 건수와 진행 건수만 추가하며 수업 본문은 제공하지 않습니다. 기존 암호화 DB 백업에 정리본도 포함되고, 수업 영구 삭제 시 함께 삭제됩니다. 이미 만든 백업은 소급 삭제하지 않습니다.

## 확인해야 할 한계

Markdown은 문서 경계를 명확히 표현하는 수단입니다. 파일 확장자만 바꾼다고 인식·번역 정확도가 올라가지는 않습니다. 공식 [프롬프트 안내](https://developers.openai.com/api/docs/guides/prompt-engineering)의 지시·자료 구분을 참고했고, [구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)의 잘림·거절 구분을 반영했습니다. 이는 NOVA에서의 특정 모델 품질 보증이 아닙니다.

구간 출처가 모두 있다고 내용이 빠짐없이 정확하게 정리됐다는 뜻은 아닙니다. 의미적 생략·잘못된 음차 복원·추정 표시 누락·잘못된 인과관계는 여전히 가능하므로 원문과 녹음을 대조해야 합니다. 전체 문맥 반복 전달은 입력 사용량·처리 시간을 늘릴 수 있습니다. 실제 개인 수업으로 모델을 호출한 품질 비교는 아직 수행하지 않았습니다. 최신 자동·브라우저 검증 결과와 배포 상태는 [HANDOFF](../HANDOFF.md)를 따릅니다.

## 비개인 예문 검증

`scripts/validate_study_note_llm.py`는 코드에 공개된 짧은 영한 혼합·음차 예문 두 개만 검사합니다. 기본 실행은 환경 설정이나 키를 읽지 않고 HTTP 요청도 하지 않습니다. 명시적으로 `--live`를 붙인 경우에만 기존 NOVA 설정으로 최대 HTTP 2회(재시도 없음)를 사용하므로 크레딧이 소모될 수 있습니다. 운영 DB·녹음·개인 수업 문서는 읽지 않습니다.

형식·출처는 실제 정리본 검증기로 확인하고, 예문의 숫자 보존·한국어 번역·문맥에 맞는 단어·부정·조건·음차 복원은 공개된 단어 검사와 생성 문서의 별도 검토로 확인합니다. 예문의 품질 검사는 운영 정리본의 숫자 변경을 저장 차단하는 검사가 아닙니다. 이 소량 검사가 모든 과목이나 긴 수업의 의미상 정확성을 보증하지는 않습니다. 생성 문서는 접근 권한을 제한한 임시 폴더에만 저장하며 공개 소스나 일반 로그에 출력하지 않습니다.

현재 공개 예문 두 개를 실제 NOVA로 확인했습니다. 영한 혼합 문맥에서 `bank`를 강둑으로 번역하고, 한글 음차 `배치 놀말라이제이션`을 배치 정규화로 풀어 썼습니다. 사례마다 원문 세 구간과 숫자·부정·조건이 유지됐고, 생성 Markdown을 직접 읽어 확인했습니다. HTTP는 각각 한 번, 총 두 번 사용했으며 응답 시간은 약 8.6초·6.7초였습니다. 이는 해당 짧은 예문에서의 결과이고 성능 평균이나 장시간 수업 품질 측정은 아닙니다.
